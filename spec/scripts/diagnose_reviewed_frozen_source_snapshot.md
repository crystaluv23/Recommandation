# Fixed40 source-completion preappend preparation

## Current bounded phase

The initial implementation provides **prepare only**. It prepares one complete
preappend source diagnosis for the exact frozen40 identities. It does not append,
materialize a new view or run another input matrix. A later separately frozen
execution may qualify/append the complete proposed batch and consume one new
view through both original720-ref matrices and40 default BasicInfo cases.
Do not implement that later phase by guessing evidence that is not yet present.

The cohort authority is the already-exported label-free case-identities artifact
and frozen40 plan, with the exact split/order/cutoffs and v6/v12 definition
scopes. Neither preparation nor later execution deserializes the old mixed
v182 envelope. Preserve all40 cases, all25 missing-financial families (BMBL plus
24 non-Anchor companies), and all24 missing market/operating families. Product,
cache, request-key and proof counts are separate denominators. No five-case
subset or outcome-based replacement is permitted.

additional_companyfacts, output, operating_candidates)` writes a new local-artifact-only output.

Bind its prior inventory and all association/source bindings; historical code
bindings are historical evidence, not requirements that current code equal them.

`additional_companyfacts` is an explicit local table, empty when none exists.
Each nonempty entry binds one of the original25 companies with exact
`company_id`, `cache`, `rawproof` and `receipt` path/SHA bindings. This permits
GPRE's separately authorized single-GET task-local managed cache and actual raw
proof to enter preparation after collection, without automatic GET or a global
raw-proof append. A production entry requires its actual retained receipt;
Receipt counters, HTTP status and byte count require JSON integers (not booleans
or floats), and cache/rawproof binding equality preserves complete canonical
JSON types. The retained singleton collector receipt must also bind exactly one
network open, HTTP response and attempt reservation (strict integers), and its
request must be `GET` with status `http_response_retained`. Contradictory request
status or counters reject even after rebinding the receipt hash.
Receipt binding is origin evidence, not a fourth proof kind passed to the
existing three-proof Company Facts profile. Empty tables remain legitimate
tests/missing-source inputs. Foreign companies or implicit replacement of
retained variants reject.

Output must be new. Install actual socket, model transport, Signal execution,
LabelStore reading and fullprepare tripwires. Do not construct a global
RawInfoStore, read LabelStore/Locked Test, load a large price archive, acquire
credentials or make any network request. No Signal apply, prepare_inputs or
research model operation is part of this phase.

## Exact Company Facts reconstruction

Visit all25 financial families. Keep every exact request/cache/raw variant and
every association from the frozen inventory, including invalid or mismatching
versions. A usable pair requires the exact SEC Company Facts GET envelope,
issuer, canonical whole response-body equality and aware retained cache clock
no later than the raw proof's original normalization clock. Validate the raw
document's full native identity and company; matching JSON keys or filename
alone is insufficient.

Record all variants, body digests, issuer/request/clock conflicts and pair
exclusion reasons. If more than one distinct valid response body remains, keep
the family ambiguous rather than selecting the newest body. Within one valid
body, deterministically choose the latest matching cache retrieval not after
its matching raw clock, with canonical absolute cache/raw paths as stable tie
breakers. Identical candidates may share a proof binding but retain all original
associations. Conflicting canonical records for one raw proof ID remain a
conflict, not a clock-selection opportunity. No GPRE cache is manufactured;
without the explicit additional binding its family is `needs_acquisition`.

For each usable family call the actual shared
`materialize_company_fact_documents` using all supported comparative history:
`period_end_from=0001-01-01`, period_end_through the original cutoff's UTC day,
available_at_through the exact original aware cutoff, and the existing standard
form/taxonomy allowlists. Preserve the approved filed-next-UTC-midnight policy,
period/tag/unit identities and retrospective/unaudited limitations. Capture a
new actual aware normalization clock, independently from the retained cache/raw
clocks. Save every typed product and the complete expected_products identity
set plus native `sec-companyfacts-normalization-v1` artifact. Whole API/raw
responses remain proof-only and are never proposed as model-visible products.

Run the existing `_verify_companyfacts_document` against every typed product
with bound cache/raw/normalization artifacts, using exactly the current three
proof kinds and full canonical comparisons. Native failures stay explicit for
that family; other fixed families are still diagnosed. A successful prepare
means the diagnosis finished, not that every source family qualified.

## Full-ID collision boundary

Before a product is marked preappend-eligible, locate that exact document ID
across **all existing source namespaces** of the actual oracle, not only the
proposed source_type directory. Native SEC IDs omit source_type; an old same-ID
record under sec_filing or an exact-form namespace must not be missed.
Use a bounded filename index or direct namespace/company/exact-name lookup;
never construct the global store or scan unrelated file bodies. Read only the
matching candidate files, bind every match and compare complete canonical
record hashes. Any different company/type/clock/metadata/content is an explicit
collision. Do not move files/markers, rename IDs, change source_type or retime an
old record. An exact same canonical record is only an existing replay candidate,
not evidence of source admission. Keep collisions and unknowns in the fixed
family report; do not append to test idempotence during prepare.
