## Frozen execution

Only root may authorize execution after code/plan review and checkpoint.
A new exclusive execution marker permanently prevents repeated execution,
including partial failure. There is no resume, retry, replacement root or
pagination. The maximum is 92 actual GET attempts, or95 with both explicit additional bindings; reused/blocked entries remain
in the fixed denominator. Each actual network attempt has a durable fsynced
reservation before opening the connection. Native pre-network quota failures
remain separate from actual opens and retained HTTP responses.

Use the existing ManagedHttpTransport, RawDataCache, RequestLedger and
SourceBudget. Massive issuer proofs use company_profile and splits use the
existing corporate_actions capability; the native MassiveClient has no getter
for these exact endpoints, so call ManagedHttpTransport.get_json directly.
SEC uses SecEdgarClient.filing_document_text through managed get_text, using the
proven literal filing metadata and saved SEC User-Agent. No production adapter,
source catalog, original 30-proof collector or admission profile is changed.

Respect Massive's existing five network attempts per rolling 60 seconds and
SEC's existing ten per second. Incorporate the bounded existing native ledger
entries and retained old collector attempt timestamps, plus new attempts; do
not gain quota by using an empty task-local ledger. Native SourceBudget remains
active. Waiting is pacing before a first attempt, never retry after failure.
Timeout is 30 seconds. No redirects or automatic retries occur. HTTP403/429,
transport, parse, provider, quota or incomplete-page failure stops that host's
remaining scope, leaving explicit dispositions for all requests. A successful
complete nonempty split ledger is retained as unsupported for the present
empty-ledger profile; it does not stop unrelated requests or become qualified.

## Evidence and credentials

Persist actual raw HTTP bytes, sanitized response headers, exact status and
sanitized response URL, started/retrieved aware clocks and byte count. Store raw
HTTP separately from its native decoded text/JSON. Decoded JSON proof bytes and
`market-request-records.json` retain the exact list fields consumed by
`_market_response`; gzip raw bytes are not mislabeled as JSON. SEC receipts
retain the existing `requests`/retry/redirect shape consumed by the response
profile, with raw_response bindings and encoding. Native cache and ledger
bindings are additional acquisition evidence, not automatic source admission.

Runtime credentials are used only through the existing launcher/environment
path and Authorization header. Do not display, persist or hash credential
values, store apiKey query parameters, or log unsanitized errors. Detect reflected
credentials in raw bytes, native decompressed text and parsed JSON before
writing any raw/decoded response or cache. Convert open/read transport failures
to a static error carrying only the exception type before the managed ledger
sees them; never forward an exception message that could echo a key. Fail the
host safely and count a retained response only after its raw file is fsynced. Saved SEC
contact headers are separately bound public request metadata. Never read a key
file or print request headers during this task.

All final rows distinguish reused, received, received-but-unsupported,
failed-typed, blocked-by-host and not-attempted states. Final source/code hashes
must remain equal; successful HTTP or a cache file is not qualification, whole
body semantic review, readiness or research progress by itself. This batch
never constructs/appends a global RawInfoStore, materializes a source view,
runs a matrix/Signal/model/fullprepare, or reads labels/Locked Test.
