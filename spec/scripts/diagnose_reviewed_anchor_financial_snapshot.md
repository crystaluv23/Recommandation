# Fixed financial-source derivation and input-only qualification

This bounded diagnostic keeps the frozen financial inventory's exact 15 cases,
15 caches, 15 legacy aggregates and 15 raw-response proof originals. It creates
new typed Company Facts products through the shared production normalizer and
qualifies them under `sec_companyfacts_filed_next_utc_day_v1`. It performs no
network, model, Signal apply, label-store or full-run preparation operation.

## Separate preparation and execution

The default execution output is the new `stage/` child of
`runs/diagnostics/reviewed_anchor_financial_snapshot_20261020_v1/`; independent
development/review evidence stays outside that child and never authorizes or
enters the source derivation.

`prepare(inventory_path, operating_input_path, output)` writes only a new local
input plan. It binds the inventory, all 45 exact source objects, the unchanged
operating review/view, the exact existing v12/18-ref definition pool, current
code, the snapshot/financial-profile/normalizer owning specs and this script's
owning spec. Historical code hashes inside old inventories are
historical evidence, not requirements that current repaired code equal them.
Preparation does not construct a global store or append any document.

`execute(output)` is a separate explicit operation after code/profile tests and
root review/freeze. A completed or partially executed output cannot be rerun by
this entry point. Partial failures retain their append inventory and artifacts;
there is no rollback, cleanup, new-root retry or automatic continuation.

Before execution, bind every pre-existing file beneath the actual source oracle
and its unchanged `oracle.json`. Use one real `RawInfoStore` on that same root;
never move an identity marker or widen the reviewed reader's cross-root guard.
Normalize each exact cache at its original case cutoff, with all supported
comparative periods (`period_end_from=0001-01-01`), the fixed standard taxonomy/
form allowlists and a new actual aware UTC normalization clock. Preserve the
cache clock and old raw-response normalization clock as separate evidence; do
not backdate the new product's `retrieved_at` to either old clock.

## Derivation and append evidence

Per case, persist the normalizer's complete expected-product identity list and
the exact `sec-companyfacts-normalization-v1` record: profile, cache/raw proof
bindings, item, selection, acquisition policy/hash and actual normalization
clock. Preserve `retrospective_api_extraction` and `requires_primary_filing_audit`
metadata. Primary-audit completion is not asserted by this policy proof.
Before any global append, pass every candidate group through the actual native
Company Facts profile verifier with its exact three retained proofs and original
cutoff. This is an in-memory profile check, not a fake original-record path or
relocated oracle marker. A failed profile stops before source mutation.

Append each new per-accession document through `RawInfoStore.append`, then load
its exact ID and require complete canonical-record-hash equality, preserving
JSON type distinctions such as `true`, `1` and `1.0`. Worker/restart document
collections use the same full canonical representation, not Python dataclass
or mapping equality. A false append result is
reported as replay, not success by itself: full canonical equality is required,
otherwise stop. Record canonical file bindings, every new file and timing.
Verify every old file's bytes and the exact allowed additions after appending
and again after all consumers. New product counts are independent of the fixed
15-case and 45-original denominators. Old aggregates/raw proofs remain unchanged
and are not admitted as financial products.

Create a new review by retaining all old operating-review rows verbatim and
adding explicit financial-profile rows with the exact three proof kinds:
`sec_companyfacts_cache`, `sec_companyfacts_raw_response` and
`sec_companyfacts_normalization`. Each admitted row points to the actual newly
appended canonical record. Materialize a separate read-only snapshot using the
unchanged native materializer/loader interfaces, then verify restart and worker
snapshot equality. Never modify or resume any old view or completed stage.

## Native input-only consumers

Reconstruct the existing ordered Registry v12/18-ref definition snapshot from
the old operating input's exact frozen authority; verify its definition hash and
all referenced spec/skill bindings. Retain the complete pool, without selecting
an easier catalog or borrowing a newer Registry version.

At each original cutoff call only `SignalExecutor.prepare_inputs` with disabled
acquisition and no LLM runner. Save all 270 exact per-ref resolutions, source
identities, period/observation coverage and gaps, plus measured per-case resolved
fractions and the existing 0.8 comparison. Do not call `execute_batch`, calculate
Signal measurements or infer semantic adequacy from a resolved status. Preserve
the old operating readiness result (0/15 reaching 0.8) as historical evidence.

The diagnostic installs a socket tripwire before preparation/execution, binds
all executing local source modules, rejects code/input/source drift and reports
actual timing without a new performance cache or batch-append API. A global
store's initial refresh and per-append tree/stat cost remain visible. Reviewed
proof verification may use only the reader's per-verification payload-local
memoization; no cache survives refresh or weakens full-byte proof checks.

## Limits

This establishes explicit retrospective Company Facts provenance and the approved
filed-plus-one-UTC-day availability policy. It does not prove an exact acceptance
instant, as-published API vintage, primary-filing numeric audit, arbitrary period
comparability, all nine financial Signals' semantic readiness, news/transcript
coverage, full48 readiness, model behavior, Fast/Slow completion or MVP success.
