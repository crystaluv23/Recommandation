# Single owned partial Reflect and blind Predictor stage

This new diagnostic freezes one historical accepted BMBL prior/Plan/portfolio
and its actual first Signal batch from the completed reviewed prefix. It runs
fresh native Reflect, optional terminal-closure Reflect, then blind Predictor
through one independent-subagent exchange. Historical Signal results are input
seeds, not new F6 execution or statements about current source availability.
No old experiment, trajectory, answer cache, correction or prediction is resumed.

`prepare(root, expectations, source_result, seed_commit)` requires a new root,
the completed fixed40 source-completion result and its current1776-document
reviewed view, and the exact immutable commit of the completed prefix. Verify
its complete checkpoint, original exchange/cache receipts, historical code and
external bindings. Export only Plan, prior, selections, results, identity/cutoff,
BasicInfo, baseline, computed metrics and runtime evaluation/source status.
The exact prior/selections/results come from accepted observations. BasicInfo
is the canonical unmasked `preflight.json.model_context` bootstrap input with
its original `requests/projections`, visibility counts and omission metadata,
not the already assembled final-context `source_index/projection_cards` shape.
The latter cannot be passed back into the native assembler. Only the allowed
computed-metric cards come from the old durable prediction envelope; baseline
and evaluation anchor come from the original Reflect request.
Never export its prediction, final state, old49/50 operations, oracle, outcomes
or future material. The new roles receive only their actual model-facing inbox.

Bind the completed source result/input manifest/plan, all its frozen source and
code bindings, current view/review/proofs, full historical seed provenance,
Registry version files, current native source, directly reused scripts and this
owning spec. Serialized binding paths are JSON strings; this diagnostic's
single `read(path)` boundary converts both strings and Path values to Path
before delegating to the shared reader. Read the actual input-manifest→plan
and result→source-review chain through that boundary, retaining exact hash
checks before transport. Mocked source loaders do not verify this connection.
Validate the prior and owned portfolio before dispatch, and verify
historical batch evidence exists exactly in current admitted PIT originals.
The independent oracle has fixed_denominator1/sample_id p01 and stays separate
from model input. It must supply limits equal to the frozen contract below;
its semantic expectations are reviewed independently, never supplied to roles.
Hash-check every nested independent-oracle binding and retain it as provenance.
The supplied completed source result and the historical prefix inputs/completion
must exactly equal the oracle's declared bindings, including path and SHA.
All other declared source-view/body references must remain in the verified
source inventory; the historical failure fixture is hash-bound audit material,
not a source of model answers.

The fixed maximum is six actual independent requests,512000 cumulative logical
reservation units and131072 per request. Every request_ready checks exact message
UTF-8 bytes plus output reservation before cache/receive/dispatch, including
replayed logical requests. Each native invocation has one structured correction.
Preserve64000 units for finalization during initial Reflect. The initial Reflect
keeps its historical nonterminal collection context. If it returns continue,
run exactly one closure with no owned selections, the same whole seed batch and
must_finalize/max_signal_rounds; no new collection action is permitted. Final
runtime metadata describes this bounded seeded stage, not a new research round.
Actual model version/internal cost and tokens remain unknown, external API cost0.

Persist/reload each accepted state, usage, request hashes and exact dispositions,
then validate against its own prior. Assemble final context with native helpers
and the real runtime-owned prediction_ready state. Call LLMBlindPredictor.predict;
the sink atomically writes exact context/prediction and verifies readback before
completion. Do not call a truth provider, apply Signals, read labels/LockedTest,
fetch, normalize/append sources, invoke fullprepare or create a trajectory/score.
Network, LabelStore, source append, Signal execution and fullprepare have guards.

Fresh roles start at66 under root dispatch, each fork_turns=none and only exact
inbox/outbox paths. submit binds the actual agent ID without changing raw bytes.
A first valid residual means the mirror correction branch is not_exercised.
Never induce an overlength first answer, replay old49 as a new answer, or create
new roots to chase corrections. Mark the branch exercised only when actual
correction input grants its residual_mirror_path and the fresh correction runs;
independent review must still verify the two authorized writes and exact final
consumer meaning. No role output is automatically a semantic acceptance verdict.

`resume` serializes through a lock, revalidates frozen inputs before traversal,
and uses only verified native cached answers during pending reentry. The frozen
absolute destination cannot be relocated to restart the same batch. A terminal
failure/budget stop cannot resume or increase ceilings. Completed restore checks
the exact immutable artifact set and original raw/inbox/receipt/parsed-cache
chain, adds no dispatch and returns the stored result. Unexpected/missing/changed
artifacts reject. Only root progress/completion/.stage.lock and exchange/.dispatch.lock are
excluded by exact relative paths; nested same-name files remain bound; completion itself is hash sealed. No production source is edited
by this stage. The one-sample result closes neither overall F7/F9/MVP nor gain.

Tests use temporary fixtures and fake offline role authors at actual transport,
parser and sink boundaries. They prove wiring, budget-before-receive, failure
terminality, no oracle/raw-answer leakage and exact completed restoration, not
fresh model compliance. Implementation tests never prepare the actual stage.
