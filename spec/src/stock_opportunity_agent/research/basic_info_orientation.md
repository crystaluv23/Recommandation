# Versioned Basic Info orientation

The existing B.requests JSON shape remains unchanged. New execution composes
five fixed actions under basic-info-orientation-v1: market_backbone,
operating_report, management_commentary, scoped_news and financial_facts.
request_id is orientation.v1.<action>. Each descriptor owns its exact description,
source routing, completeness recipe and internal fixed query; only positive
integer lookback/count within its published bounds are Plan parameters.
Descriptions, source families, query and completeness knobs are not free research
instructions. Plan query must be absent or null. Unknown raw request keys reject before archive coercion. The compiler may inject a menu-owned
fixed query to locate orientation passages; that recipe is not a Plan parameter.
Underlying RawInfoRequest remains general for Signals/deep research.

One compiler is authoritative for proposer admission and every new direct core
execution, before resolver/model calls. It validates raw proposals before legacy
integer coercion and validates typed policies again at execution. New producer
prompts disclose complete descriptors rather than merely a source whitelist.
Default Plan uses the same descriptors. Historical from_dict/to_dict remains
readable without rewriting archived bytes; old free policies cannot silently
enter new execution. New run contracts bind the menu version; old frozen code
and completed pointers retain their original interpretation.

The operating action orients business model, risks and segment economics from
available annual OR interim reports, without asserting all facts were supplied.
Default count is two: prefer an available annual and latest interim, then other
eligible material. With count one prefer annual background if available, else
latest interim; an interim alone satisfies periodic-source availability. No
annual-only requirement is added. Periodic forms are exact 10-K/10-Q/20-F/40-F.
Current 8-K/6-K and amendments remain legal generic filing evidence but their
form alone cannot prove periodic/business coverage; missing periodic source is
explicit completeness gap. The same ordering applies before provider body
limits and after append/requery. Generic non-orientation filing ranking remains
unchanged. Use the fixed broad business/operations/segments/customers/risks recipe,
not issuer-specific wording or known answer snippets. Actual model projection
must show substantive business material in a positive, not just select a file.

SEC exact-form matching requires authoritative form metadata or an exact typed
source form. Titles mentioning a form are not proof. Reject substring/suffix
lookalikes and conflicting typed-form metadata. Amendments are not silently
matched as their original form; generic reading remains legal. Provenance,
PIT, literal offsets, bounded budgets and omitted/unknown visibility survive all
selection/projection stages. Source availability is not semantic completeness.

Available means the eligible frozen local pool plus documents actually obtained
under the existing bounded acquisition contract, not the provider universe. A
complete local periodic-source hit is reused; an unqueried provider is unknown,
not proof that no newer interim exists. Differing visible pools can yield
different selected reports. Same-pool cached/fresh/append selection is identical;
annual-OR-interim is not strengthened to require both or force extra retrieval.

Capability admission uses the resolver's existing semantic source-route
compatibility, not literal equality between fixed routing and inventory aliases.
For example sec_filing/prices may support operating_report/market_backbone while
the Plan still copies the canonical filing/market_data templates verbatim. The
producer exposes compatible action IDs beside raw available source types;
unregistered unrelated routes remain unsupported. This does not let a Plan
rewrite template source types or turn inventory compatibility into coverage.

The output advertisement matches admission: copy one or more distinct available
actions, at most once per action, with required integer lookback/count values.
No prompt invites new B descriptions, competitive queries or exact-form routing;
those deeper research questions belong in H skills and the research loop. Menu
routing remains target-issuer scoped and unsupported form coverage stays a gap.
