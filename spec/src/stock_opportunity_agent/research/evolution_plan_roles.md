# Evolution Plan Roles

Before Reflect constructs any model request, validate the complete current
Signal batch through the shared canonical-evidence PIT input guard at the
actual evaluation instant. A bad serialized result rejects the stage with no
role dispatch, including forced terminal paths. Critic and routing prior-result
views apply the same guard when their case cutoff is available. Invalid source
input is not a candidate/Plan content error and cannot enter typed model-output
correction. The exact raw result remains local audit evidence.
Predictor checks existing final-context Signal cards before estimation or
dispatch, so loading an old context cannot bypass final assembly. Contexts
containing Signal results require an explicit aware runtime prediction instant.

## Executed need dispositions (2026-10-19)

Reflect uses one transient patch envelope: the eight canonical ResearchState
fields plus `need_dispositions: []`. Its existing model call authors dispositions
alongside the state delta; ResearchState's permanent schema stays unchanged.
Each disposition contains exactly `need_index`, `answer_scope` (`full`, `partial`,
or `unanswered`), `residual_need` (null or text), `evidence_refs` (exact
`signal_ref`/`evidence_group`/`evidence_index` tuples), and `reason`. Routing
declares intended answer scope; the executed evidence owns the actual claim.
Routing need matching does not require advance proof that issuer data exists.
It still requires the callable to be capable of the requested measurement:
latest-comparable selection is not arbitrary FY or share-tag selection.
Reflect checks the actual operands/periods before accepting a disposition.
Measurement coverage is independent of answering a need: partial measurement
may fully answer a narrow question, sufficient measurement may answer only one
part of a compound question, and a different period cannot close the target.
An unanswered disposition preserves the need exactly. Its evidence refs may be
empty or cite valid adopted current-batch evidence explaining a period or scope
mismatch; those refs do not claim the need was answered or authorize closure.

Judge the requested object, static attributes/terms, dynamic status and actual
fact-coverage period separately from source public availability. An umbrella
question cannot be narrowed to static attributes while silently dropping its
unsupported dynamic state or later, cutoff-bounded coverage. A public timestamp
does not extend the observation period. Already-public forecasts remain valid
answers to questions about those forecasts, not proof of later realized states.
A partial residual must preserve every unsupported requested facet and time scope.
The reason must explain which requested facets/coverage the actual evidence
answers and what remains missing; it never substitutes for the residual.
If that cannot be expressed losslessly as a genuinely narrower 1–300 character
residual, use existing `unanswered` with null residual and retain the original
need byte-for-byte. Valid evidence can still be adopted independently. Do not
lose a facet to satisfy the length bound, move it only into the reason or create
an unowned substitute need. These are authoring duties, not new semantic fields,
keyword gates or authority for runtime to invent missing facets.

The prompt uses `need_transition_contract.required_disposition_need_indices` as
the exhaustive current-invocation target set. An empty set requires
`need_dispositions=[]`, even when a terminal closure sees the previous Signal
batch and many unresolved indexed needs. Those needs remain preserved; visible
evidence is not new ownership. For an illegal owner row, correction explicitly
requests removal and exposes the exact allowed indices, never a fabricated
unanswered row or rewritten prior ResearchState to make that row fit.

The complete envelope is validated before success; unknown fields are never
silently discarded. Typed corrections and fallback retain their exact authority.
Quarantining evidence requires revalidating dispositions and need transitions;
runtime must not invent a full answer to complete a state. Only after complete
validation succeeds does the adapter emit bounded `need_dispositions` metadata:
`prior_state_hash` binds the canonical prior state, and `items` contains validated
rows with their exact prior need text. Failed intermediate parses emit no accepted
disposition metadata. No additional model role or call is introduced.

If raw state normalization fails, Reflect aggregates independently decidable
disposition issues into the same correction feedback. The diagnostic pass checks
metadata shape, ownership, residual and executed tuple validity without treating
an invalid state as adopted evidence. It returns issues only, never accepted rows
or need-transition authority. A corrected envelope still passes the complete
state, adoption, disposition and transition validators before any metadata is saved.

The final Predictor's existing state-evolution view and compact posthoc/critic
views retain these actual dispositions, separate from Routing's earlier intent.
They establish authored provenance, not automatic semantic truth.

## Admitted measurements and unverified effect

Actual selector cards use the Signal Library's shared exact-version
`measurement_scope`, also used by `SignalCard`. Retrieval source/comparison/period
requirements remain distinct from actual deterministic callable documentation
and configured parameters; conflicting version prose and implementation remain
visible rather than rewritten. An optional `set_deterministic_functions` receives
the executing map from core before selection. Without that injection the callable
contract is unknown, never inferred from a built-in function name. Jev's compact
card producer follows the same projection and setter. All original eligibility
filters, card membership, ordering, PIT checks and portfolio budgets remain.

Selector cards disclose frozen `research_status` for admitted versions. Technical
admission authorizes use, not effect claims; choose by actual information need
and data applicability. H_reflect receives status only for its current batch via
the controller's optional frozen-status setter. Predictor receives status beside
each actual measured result in its existing evidence assembly. Fixed prompts
distinguish a valid measurement from demonstrated contribution and never force
higher magnitude classes merely because a measurement targets magnitude.
Legacy versions without a new admission record receive no invented status.
Cards, profiles and controller status use the Registry's recursive plain-JSON
projection before document/read channels copy requests. Outgoing mutations cannot
change the frozen source; shallow copies of frozen nested lists are insufficient.

## Fixed Predictor role authority (2026-10-02)

Plan proposal participates in the shared mechanical repair registry. After
snapshot-bound patch application and scope checks, exact duplicate source-family
members may be removed without changing membership or research content. The
normal raw request, closed family menu and complete Plan validators then run.
Original responses remain immutable and typed repair operations are reported.

H_analyse evolves evidence organization/weighting, while the fixed Predictor
always owns the final direction and conditional magnitude output. Its fixed
shell overrides a conflicting Plan instruction to omit classification or the
mandatory output. Proposer and Critic disclose the same division of authority;
the absence of classification inside H_analyse is not proof that the system
lacks magnitude prediction. Any causal quality attribution still needs evidence.

The shared structured reflection envelope admits only `reflection_items`,
`selected_reflection_refs` and optional `no_findings_reason`. Signal association
refs belong inside individual authored items and must be supported by that
item's source handles; they are never a top-level envelope field. Fixed prompts
must name this location. Unsupported envelope containers receive typed
whole-field remove authority, including empty arrays; deleting their members
does not remove the unsupported key. Initial feedback also checks every
parseable item independently alongside envelope issues, then fully revalidates
the merged response. Valid siblings, citations and scope are preserved.

Source wording describes its own availability time. Initialize/Reflect must not
promote an expired dated event or an old source's “currently” into a claim that
it remains current at prediction_time. Predictor receives the cutoff explicitly
and retains per-card availability dates; posthoc uses that same cutoff.

The blind LLM Predictor exposes an optional exact initial-request token estimator.
Estimation and execution share one system prompt and payload, including transport
identity projection and reasoning headroom. It does not estimate research truth
or guarantee unlimited correction attempts fit the remaining budget.

Price-baseline distance is outcome-definition arithmetic, not independent
counter-evidence against a surge. Predictor instructions distinguish it from
source-backed contrary evidence and require computed price-change cards for
quantitative price-trend claims; an absent computed window remains uncertainty.
Computed returns must retain their own first/last observations and dates;
unrelated Basic Info prices cannot be attached to that return. Explicit prose
of the form "from X to Y, a Z% return/increase/decrease" is checked for arithmetic
consistency, with rounding tolerance and signed decrease handling. A contradiction
creates a typed issue for that single reason/uncertainty; shared incremental
correction preserves other valid fields and revalidates the complete prediction.
This bounded check does not claim to verify arbitrary prose or forecast quality.

## Purpose

New proposal output contains the four strategy fields plus
`used_experience_refs` (empty is allowed). All five fields belong to
the same root Plan object; the prompt's
opening instruction must not exclude the adoption field or imply a separately
closed strategy object. Basic Info queries remain outside the closed orientation
menu, and the appended output instructions must not advertise `B.requests[*].query`
as an optional supported field. This applies to original proposals and full
corrections after an unparseable response; it changes no parser or repair authority.
Each adopted ref must have appeared in
an actual initial brief, directory page or item read in this proposal. Parent
metadata and undisclosed/deferred handles do not grant adoption authority.
Runtime binds the complete final disclosed working-view snapshot and persists
the adoption metadata. A new proposal that omits `used_experience_refs` receives
typed add-only repair authority for this field; omission cannot mean no adoption.
Missing adoption metadata does not suppress independent strategy validation:
runtime checks the otherwise parseable four fields with adoption still unknown
and combines the missing-field obligation with their owning typed issues. This
is a diagnostic view, never an accepted new Plan or an inferred empty adoption.
After applying a typed correction, the drift check uses that same issued
contract's operation paths. It cannot reject an explicitly authorized metadata
addition merely because another obligation repairs a strategy field. All
unrelated fields remain immutable and the entire merged Plan is revalidated.
Invalid lists/unknown refs receive typed local repair authority for this field
alone. Persisted legacy Plans remain readable with unknown adoption; the legacy
record loader is separate from validation of newly authored role responses.

Implement structured adapters for Plan proposal, criticism, adaptive research,
Signal retrieval, blind prediction, and Plan reflection.

## Invariants

- Source-fact interpretation uses the shared object/unit/period/event instruction
  on every fixed role request, including initial authoring and correction.
  Initialize/Reflect, Predictor and retrospective Plan/case/Round roles retain
  a project's cost and capacity as attributes of that project, rather than
  interpreting them as separate contracts or independent catalysts. Distinct
  source-established events remain distinct. This prompt requirement does not
  certify arbitrary prose, change a saved prediction or authorize a state edit.

- H_init describes the actual final Predictor visibility: the final assembly
  includes Basic Info cards, accepted state and later stage products. Its
  instructions must not claim that only the compact state is forwarded.
  Initialize still retains a bounded set of material sourced claims.

- Adapters translate model output into core protocols; they do not own engine
  state or commit pointers.
- Signal retrieval, Reflect, Predictor and every authored reflection level share the Signal
  Library's explicit execution-status instruction. `domain_unavailable` is a
  normal domain coverage outcome, technical statuses are listed separately,
  and legacy missing status is unknown. Prompts do not use an ambiguous
  "former/latter" reference to assign these classes. Model views preserve the
  same distinctions before compact posthoc projection; immutable old predictions
  and Experience are not retrospectively corrected by this prompt alignment.
  Prior routing-result cards retain recorded execution status without private
  diagnostics. An unavailable value alone cannot establish missing issuer data
  or exclude a sibling measurement with the same data requirement.
- Prediction-time roles never receive labels or target identity.
- Post-label Jev feedback includes deterministic proper-score and concentration
  diagnostics. Post-hoc reflection and the Plan critic must explain recurring
  low-support correct calls, high-confidence errors, and collapsed magnitude
  choices. Proposer-visible meta derives the same aggregate from immutable case
  feedback and requires a concrete Plan change or explicit defer/reject rationale;
  confidence itself remains excluded from fitness and is never maximized alone.
- Correction and fallback behavior delegates to the shared validators. Plan
  proposal corrections are checked with the same field/member granularity as
  controller corrections: a leaf path such as `B.requests[i].description`
  authorizes only that field, never sibling fields, whole-request
  replacement, or inserting another request.
- After bounded correction, typed answer-ownership failures may retain the same
  selected Signal as context only, with full revalidation and unresolved needs.
  This removes an unverified routing claim without inventing research evidence.
- Duplicate direct ownership is detected across the complete selection set.
  The validator authorizes context-only conversion per exact conflicting row
  and Signal identity. If exactly one full-answer claim exists, it is retained
  unchanged and partial claims become context only; otherwise every conflicting
  direct claim becomes context only. This preserves selected Signals and target
  indices, never chooses an ambiguous owner, and runs complete validation.
  Typed mechanical conflict repair precedes LLM correction; other ownership
  failures retain their existing bounded semantic correction policy.
- ResearchState summary counts, text lengths, and summary bytes are advisory
  compression targets. Transport token budgets remain hard limits; evidence,
  provenance, PIT boundaries, and need ownership remain validated.
- A terminal batch containing only unavailable Signals has no new evidence to
  reflect on. Return the previous state with only decision changed to finalize,
  without a model call or fabricated findings.
- Information Plan proposals express cross-issuer business/risk research through
  the generic `filing` capability unless an exact SEC form is itself material to
  the research question. They must not assume every U.S.-listed issuer files
  domestic `10-K`/`10-Q` forms; the resolver selects applicable domestic or
  foreign operating reports while preserving exact-form restrictions.
- Plan proposal retains the complete additive FIFO in storage but receives a
  bounded brief working view. Each brief keeps its source handle, applicability,
  limitations and verification state. The role can request registered original
  units with `read_refs` before returning a Plan; each disclosure is masked,
  validated, bounded and audited under the exact request preflight. Unknown,
  repeated, over-budget and cross-role reads fail closed; no arbitrary path is
  resolved. Unread/omitted history remains explicit and available in storage.
- Case, Plan and Round reflection author structured `reflection_items` with
  full detail and an actionable `brief` together. Higher layers may select
  lower items unchanged, or add their own explicitly sourced insight. Runtime
  supplies source catalogs, stable item IDs and deterministic outcome facts;
  model-authored success/failure claims cannot contradict them. Existing string
  categories remain derived compatibility projections, never a second authored
  output. Legacy archives load unchanged and are marked unreviewed in views.
- Critic and Round inputs also use bounded brief/catalog views; neither may
  conceal an unbounded full trajectory or source catalog beside a bounded
  brief. Complete anonymous original units remain available through the same
  finite read/browse exchange (three requests, 48,000 aggregate UTF-8 bytes).
  Case-level correctness and aggregate diagnostics remain runtime facts. Read
  usage is counted with the owning role and every transmitted request is
  persisted by the normal caller. Partial coverage is explicit, never an
  assertion that omitted evidence does not exist.
- Retrospective prose may discuss observed probability distributions and time
  horizons. The Plan-instruction semantics filter must not reject the very
  calibration diagnosis requested by a reflection prompt. Fixed semantics are
  immutable in runtime and validated when an actual Plan is proposed.
- H_reflect emits snapshot-bound state operations; runtime owns copying and
  retaining unchanged state. The same ordinary evidence, need-ownership,
  temporal and whole-state checks run after assembly. The first-answer
  prompt itself discloses the text-array field shapes (never an evidence
  object), the open_questions versus next_information_needs separation with
  exact-string deduplication, and the numeric-belief copy rule, so these
  validator obligations are visible before any correction is spent. Structured correction
  returns only authorized operations against the latest failed assembled state;
  a valid sibling is not rewritten to repair another sibling. A complete object
  is only necessary when no usable structured baseline exists.
- A `partial` answer's residual need must retain the targeted information
  need's temporal scope. Production injects the actual runtime prediction
  date into the Signal Retrieval Agent through the same optional
  `set_evaluation_context` setter the controller uses, resets it per case so
  reuse cannot carry an earlier cutoff, and exposes it in the routing payload
  as control data. Explicit dated and symbolic prediction-time cutoffs are
  validated alike against that actual date through the shared bounded-residual
  representation: routing rejects a residual exactly when the reflection
  temporal guard finds no bounded restatement (realized future facts, an
  invalid parent, or an unbounded parent that lends no cutoff or framing),
  and a representable literal is accepted while the consumer normalizes once
  through the same shared rule, so producer and consumer never demand
  contradictory exact strings. The producer correction names the actual
  prediction boundary, the inherited cutoff clause, and the framing marker,
  so a truly unrepresentable residual is repaired before any Signal executes
  instead of failing only at the pre-reflection boundary. Called without a
  runtime date, routing never fabricates a date, parent year, or present day:
  it keeps only the sound dateless explicit-cutoff check, and a symbolic
  cutoff alone triggers no dateless producer rejection. Historical residuals
  that reference only years at or before the actual prediction date stay
  accepted and are never reframed as forecasts.
- Reflection exposes persisted Routing scope as an expectation, not a state
  transition mandate. A legacy expected residual cannot reject the current
  Reflect call or authorize deletion before executed evidence is considered.
  The actual authored disposition and resulting state must both satisfy the
  runtime prediction boundary; an invalid actual residual never authorizes
  deletion or completion. Without a runtime evaluation context no date is
  invented, and missing actual dispositions conservatively preserve the need.

## Shared stage boundary (2026-10-01)

Predictor, Posthoc and Plan Critic preserve runtime-owned Signal execution
status in their model views. Reflection instructions distinguish validation,
transport, permanent, budget and authorization failures from domain-unavailable
source evidence. A technical gap may support a technical repair action, never
an economic absence claim or a lesson that a valid factor failed to predict.
Historical compact contexts without status remain unknown; no consumer invents
the cause from `unavailable` alone. Round and Slow source reads retain the same
case/Plan provenance and the original execution records.

Follow [stage contracts](stage_contracts.md) for dependency checks, omissions,
partial mechanical repair and immutable accepted units. A newly resolved
question conflicting with an unanswered retained need publishes both correction
paths. Exact runtime restoration of that need may remove only the explicitly
identified unsupported newly resolved question. The final Predictor input is
the typed assembled stage products, not only the final state or full raw prompts.

Research controller, blind Predictor and case posthoc adapters use the shared

See the owning [shared arithmetic contract](evolution_output_validation.md#shared-runtime-price-arithmetic-2026-10-02).

The initial reflection contract also names threshold-bound projections and
missing-projection caps as mandatory price-proof gates. An optional business
catalyst assessment does not authorize a new screening prerequisite.

## Reflection statistics ownership (2026-10-02)

Plan Critic supplies the same runtime-owned statistic handles as the later
Round/archive index. Critic registers existing metrics, magnitude and completion
products after building the authoritative case index. Round derives its handles
from the approved per-Plan model projection, including available cohort metrics.
The shared initial reflection contract requires citing `runtime_plan_statistics`
for numeric evaluation claims and naming the owning Plan/cohort/population.
A case source never establishes aggregate statistics. Round compares per-Plan
values and cannot call one Plan's combined cohort the pooled round. Legacy
statistics-unchecked briefs are retrospective material to inspect, not verified
statistical evidence. Shared repair authority permits exact source/scope and
text changes; it never permits editing runtime statistics.

## Computed window visibility (2026-10-02)

Controller keeps the runtime typed compute cards separately from their readable
model view, for State period validation. Readable summaries include literal
endpoint dates when supplied, so the required distinction between trading-day
windows and the calendar-month outcome horizon is visible on the first call.
Prediction and Posthoc receive the unchanged typed cards. Exact window-label
repair uses the shared output validator and never changes the metric/window.
In-loop computed cards join validation before the returned state is parsed and
remain visible on subsequent reflections in the same case. Initial case setup
resets this context even when no market metric is available, so a reused
controller cannot carry another issuer's computed window into validation.
Initialization/reflection prompts use runtime anchors and cards to orient
qualitative judgments and evidence needs. They do not request numerical control
restatements in current_beliefs, contradictions or supporting_evidence. Literal
issuer facts still follow existing quote/claim rules. No source metadata/date or
filing-form identifier is invented inside a quote to justify a numerical claim.
State need not create a citation for a runtime control: the unchanged control
and Basic Info blocks are assembled separately for Predictor.

## Posthoc realized-return boundary

Posthoc names the fixed runtime outcome denominator on its first request. Its
shared content check binds explicit realized max multiples/nearby percentages
to the revealed outcome and original anchor; different named denominators need
their own arithmetic. This contract is post-label only and is never added to
blind Predictor context. The reflection envelope combines independently detected
raw text issues with action-policy issues before source/item construction, then
validates the full assembled result. Salvage invokes the same role check and
cannot keep a rejected quantitative statement. Field-local semantic repairs keep
all other items, sources, saved predictions and outcome records unchanged.

## Fact inference correction

Shared reflection authoring explicitly separates observed outcomes from claimed
weighting/signal sufficiency. The first correction frontier includes every
invalid fact brief/detail and replace-only dependent kind authority for the same
row; unrelated items, sources and outcome claims remain immutable. Canonical
ingestion and salvage revalidate the same boundary. Historical model views
disclose `legacy_inference_unchecked` without modifying archived originals.

For every parseable reflection package, independently validate each row
against canonical source/category/outcome rules before issuing the first
correction. Those obligations join the same frontier; a new interpretation
guard must not conceal an already-detectable category error behind another
round of model correction. These diagnostic rows never register new evidence.
Each independent invalid row contributes its first actionable typed issue,
including any linked category/scope/source dependencies, even when no text
policy issue exists. Whole-package revalidation remains required after patching;
this does not enlarge operation permissions or certify arbitrary prose.

The initial Plan/Round contract distinguishes aggregate statistic sources from
individual canonical outcomes. Statistics cannot populate an outcome claim's
boolean. Aggregate-only observations use an appropriate permitted non-outcome
category, or read actual case outcomes when making success/failure assertions.
The runtime never invents claims or silently recategorizes authored content.

## Bounded Raw Info navigation (2026-10-07)

The Reflect adapter advertises the data-owned catalog's cursor interface as
`{"inspect_document_catalog":{"cursor":20}}`. Cursor bounds and PIT selection
remain owned by `data/disclosure`; the adapter rejects malformed or repeated
page requests and counts paging, fetch and compute against the same existing
two-exchange budget. Budget/candidate-stop exceptions retain the actual usage
accumulated in earlier exchanges and propagate unchanged rather than becoming
domain conclusions. It preserves the initial catalog and every additional page
in later authoring/semantic-correction requests rather than hiding earlier reads.
Fetched bodies and computed cards are likewise retained across semantic correction and forwarded
through the case provider into final-context assembly and ordinary persistence.
Fetches fail closed for another company or future availability, including batches
with one otherwise valid entry; no partial view batch is persisted. Repeated
entries within one fetch batch are rejected as well as repeats across exchanges.

Document-channel provenance is readable by Predictor. It does not manufacture
an admissible State citation: the fixed Reflect prompt names the existing
Basic Info/Signal reference boundary explicitly. Catalog metadata remains
metadata; neither a page read nor a correct parser result proves source truth,
complete research coverage or prediction gain.

## Mechanical-only correction channel (2026-10-02)

The document-channel wrapper passes a runtime-issued
`state-patch-mechanics-repair-v1` request through without adding a document catalog
or exposing fetch/compute exchanges. This request repairs only supplied patch
operations; its complete original role validation still executes locally.
Ordinary research and semantic corrections retain the existing PIT data channel
and complete evidence inputs. A model cannot promote a document-read answer into
a mechanical repair: the nested patch contract rejects that output shape.

Critic trajectories retain a compact `basic_info_source_index` from the saved
final source index, or saved model Basic Info when no final index exists. The
same visibility projection as final/posthoc retains both omission layers and
markers without repeating source bodies or granting citation authority. Missing
legacy fields stay unknown; do not infer complete reading from a resolved
request, a projection count, or an empty marker list. Existing role-boundary
identity masking applies to the whole summary.

H_init instructions name `visibility_unknown` alongside partial/omitted views,
explain null stage flags as unknown, and keep omission markers as discovery
hints rather than evidence. These are general visibility semantics, not
source-specific answer instructions.

The final critic `trajectories_view` whitelist must retain this visibility
summary after reflection-memory source registration; a correct intermediate
trajectory helper is insufficient if the actual caller payload drops it. Test
the final anonymized pending messages as well as compact helper results.

The final critic request serializes complete visibility descriptors into
payload-local `basic_info_visibility_profiles`; each case row keeps profile_ref
and full projection ids. The instruction tells the critic to read both as one
row, with null still unknown and markers still non-citable. Exact decoding must
match the complete trajectory helper and retain identity masking. Native
128000-byte initial / 176000-byte post-disclosure offline acceptance limits
remain unchanged. No budget increase or visibility-field removal is allowed to
fit the envelope.
