# Evolution Output Validation

## Purpose

Parse and validate structured role output, produce machine-readable issues,
and apply only explicitly allowed deterministic recovery transforms.

## Invariants

- Proposed Plan instructions use the same narrow mandatory-proof gate check as
  authored reflection actions. Quantified valuation analysis may be useful but
  cannot become a requirement for a positive opportunity judgment. Reflection
  correction changes only the named brief/detail; citations and sibling lessons
  remain unchanged. Ordinary retrospective probability analysis remains permitted.
  Detection recognizes explicit mandatory price-proof wording within a sentence;
  ordinary business quantification, negated gates and optional analysis remain
  permitted. It is a bounded contract guard, not a semantic quality oracle.
  Offline memory-protocol fixtures may compose a new proposal using the current
  default analysis instruction when an archived parent contains a prohibited
  proof gate. Keep the original parent and evidence immutable and disclose that
  the proposal is scripted; this does not prove historical research quality.
- The compact posthoc view retains runtime-computed metric cards from the original
  Predictor packet, so numerical price-shape reasoning remains checkable.
- Validation never infers write authority from diagnostic prose.
- Scoped correction preserves unrelated valid siblings byte-for-byte.
- A recovery transform must be generic to the declared schema; it must not
  encode provider-, company-, or case-specific exceptions.

## Mechanical repair ladder (round 31)

Structured role outputs pass a deterministic repair ladder before any LLM
correction is spent. L0 completes JSON truncated at the output ceiling
(closing open strings and the bracket stack, dropping dangling commas or
colons, stripping code fences) and accepts the candidate only when the
complete unchanged parser validates it; roles that drive ``complete_json``
directly (module-staged materialization, the Plan proposer) receive the
same rung through ``complete_json_repaired`` or an inline rescue, while
the mining controller's tiny action objects keep their own retry state
machine. L2 repairs reorganize model-provided information where the
correct action is unique: registering claim-cited resolvable refs into
``source_refs``, narrowing a reflection item's declared scope to its
citation closure under union semantics (the declared scope becomes
exactly what the item's citations cover) via the ``repair_resolver``
wired by the critic, round reflector, and posthoc reflection, splitting
a mixed success/failure-axis item into its two single-axis forms with
fixed counterpart categories, removing open questions that repeat a need
byte-for-byte, and dropping empty text rows. Row-level salvage applies
the same chain per row before dropping, replacing repaired rows and
recording them under normalized paths. Applicable deterministic fallbacks run before LLM correction for their typed
mechanical issues even when unrelated issues remain. Exact runtime-issued need
restoration is mechanical. Each transform is followed by full revalidation;
unresolved issues and transformed candidates become the next correction base.
Partial progress is retained but never accepted as a valid complete object.
A bounded visited-state loop prevents oscillation. The
anchor-guard evidence-availability vocabulary includes bare verb forms
(``disclose``, ``publish``, ...) beside participles, and misplaced
evidence objects in research-state text arrays flatten to their unique
prose field (``claim``, else the sole string field); rows with several
string candidates stay for LLM correction. The ladder is general by
construction: text-array fields derive from the owning ``ResearchState``
model instead of a copied list, the mechanical fallback gate codes are
single-sourced (``MECHANICAL_FALLBACK_CODES``), mixed-axis splitting is
level-aware when the salvage path supplies the level's category
vocabulary, and repair families register against an open
``REPAIR_CHAIN_REGISTRY`` keyed by shape predicate — a new output schema
joins the ladder by registering a family, not by editing the dispatcher. Every repair is a typed operation
with before/after values emitted as a progress event; the validator —
never the repair — remains the arbiter, and anything ambiguous (values,
semantic choices, hallucinated references) stays with the bounded LLM
correction or explicit failure.

## Incremental response and correction boundary

BlindPrediction shape/enum guards publish exact missing, unexpected and invalid
field scopes. Magnitude/judgment consistency and a positive judgment contradicted
by every stated reason publish explicit alternative repair groups, retaining
their coupled fields. Empty required reasons can append one grounded reason.
These typed guards preserve the existing prediction semantics and are rerun on
the fully merged output; diagnostic prose grants no extra authority.

Plan market-backbone, source capability/scope, executable-skill and fixed
Predictor-boundary guards publish the exact Plan component or field they own.
A parseable untyped failure cannot silently request a complete Plan replacement.

Roles opt into the shared incremental contract with `output_patch_base` for a
normal state update and/or `patch_corrections` for semantic repair. Production
H_reflect uses the previous validated ResearchState as its delta base. A
parseable failed object is corrected only through typed operation permissions
from its owning validator, using the [state patch protocol](evolution_state_patch.md).
Corrected full objects are not silently accepted by this path. A role whose
initial JSON cannot be parsed may ask for a complete object again; a parseable
object without typed scope grants no new mutation authority.

Normal requests advertise both the incremental response contract and the later
correction protocol before a failure occurs. Correction requests include the
latest merged full object for reference, its exact base hash, current typed
obligations, permitted operations, and any rejected-patch diagnostic. Model
output contains only operations. Merge first, then run the original complete
parser and semantic validator. If one authorized correction succeeds while
another remains invalid, the merged object and its newly computed issues become
the next baseline; valid siblings are never regenerated. A patch-envelope or
scope error does not replace semantic failure with a generic error, discard prior
progress, or consume an unprocessed member.

Patch attempts share the existing bounded correction and token/cost budget.
Duplicate transport prevention still hands an existing typed frontier to the
deterministic fallback. Budget/provider/approval failures retain their existing
control-plane behavior; partial corrections do not turn them into domain facts.

When a Signal quantity-grounding issue says that a missing literal exists in
another evidence location of the same exact Signal, the machine-readable
obligation must authorize the minimal provenance coordinates needed to use that
location (`evidence_group` and `evidence_index`) as permitted dependencies of
the rejected claim. The claim remains the required change path. This permission
does not authorize changing `signal_ref`, unrelated evidence rows, or any other
ResearchState field. A corrected tuple is accepted only after the ordinary
Signal catalog, canonical-span, quantity, point-in-time, and whole-state
validators all pass. Merely switching an index while leaving another claimed
quantity unsupported therefore makes scoped progress but remains invalid and
must receive the next truthful validation diagnostic; it must not be projected
back to the original invalid tuple or terminated as a byte-identical retry.

Ordinary structured correction obligations use their explicit change paths and
permitted dependency paths even when a Controller enables exact compaction
scope. The compaction-specific scope resolver runs only for actual compaction
obligations; absence of compaction must never disable ordinary sibling
preservation. Scoped drift detection and projection use the latest invalid
output as their baseline: a later correction must not silently revert a repair
that exists only in that latest rejected output. When a Controller enables
exact compaction scope and ordinary issues do not declare their write scope
complete, an applied projection must pass full revalidation. A projected
correction that fails revalidation may extend its copied paths only with paths
named by structured revalidation issues raised against the projected object
itself; diagnostic prose grants no scope. A discovered compaction issue never
grants its container-root path: the extension applies only the exact removal
paths named by that issue's repair metadata, and a compaction issue without
removal metadata grants no extension at all. The model's complete corrected
object never stands in for the projection: remaining drift of any kind —
scalar, nested-leaf, indexed-item, or list membership, including same-length
membership rewrites — fails closed with actionable feedback.

When a safe projection exists but fails revalidation, the next correction
attempt must carry that projected object as its invalid output together with
the projected object's actual new validation diagnostics: safely repaired
fields are preserved, unrelated drift stays discarded, and the follow-up
correction request therefore differs from the previous correction request
instead of replaying it byte-for-byte into a cached identical response.
Retrying the original failed output and original obligations after a
discovered projection is a stall defect. When no safe projection exists, the
original invalid object and its original obligations are retained unchanged
for the retry, and that one retry's `validation_error` additionally carries
the drift diagnostic (unauthorized changed paths plus the preserve-unchanged
instruction) so the retry request itself still differs from the first
correction request; the drift note never widens the authorized repair scope,
and the unchanged scope validator still rejects a drifted retry.

When the correction budget is exhausted, the deterministic
evidence-grounding fallback may restore the exact prior literal named by a
uniquely anchored Basic literal identity obligation (replace-only authority
plus an exact prior literal in its repair context) and may remove rows whose
obligations carry explicit remove authority; restored literal paths are
reported as normalized paths. A literal restoration alone is still
progress: an obligation set with only identity restorations and no
authorized removals is repaired, after safely validating the restoration
index and the target row's type against the failed output. The remove-only
identity codes (novel Basic ref, ambiguous prior literal) evict their named
row only when their own obligation carries remove authority; a
replace-only or add-only obligation of those codes removes nothing. Every
fallback result is accepted only after revalidation through the production
parser. It still declines every obligation without
such a deterministic repair, so ambiguous literal substitution, invented
Basic refs, and any unanchored edit fail closed instead of being silently
accepted.

The transport-level identical-request guard remains fail-closed, but it is not
the terminal owner of a role that already has a typed invalid object and typed
obligations. If a later correction would be byte-identical, the role records the
no-progress diagnostic, sends no duplicate request, and enters the same bounded
deterministic fallback described above. A successful fallback is fully parsed;
an ineligible or still-invalid fallback remains a candidate rejection. For
`claim_quantity_not_supported`, same-row `evidence_group` and `evidence_index`
dependency paths are source-coordinate alternatives, not independent assertions;
when the authorized repair removes that entire evidence row, those coordinates
disappear with it while separately named beliefs or contradictions are removed
under their own dependency authority.

Field and member granularity is preserved at every path-expansion step. A
leaf path `root[i].field` authorizes only that field of its member; it never
authorizes rewriting sibling fields, replacing the whole member, inserting
new records, or removing the parent row. Whole-member deletion authority is
never inferred from the existence of an indexed leaf path or from whole-object
validity: it requires specific validator metadata — the owning issue's
`authorized_member_removals` repair context naming the exact member paths —
or an obligation that itself names the whole member `root[i]` while its
allowed_repairs permit `remove`. A supplied member-removal allowance mapping
without an entry for a collection root authorizes no removal in that
collection at all: a missing or empty allowance root is fail-closed, never
a default under which every covered slot becomes removable. A leaf `remove`
repair never becomes parent
removal without such an explicit whole-member target. Only an exact member
path `root[i]` authorizes whole-member replacement, and it authorizes
replacing that one member with exactly one returned row: deleting that
member additionally requires the slot's own explicit removal allowance, and
returning several rows where that one member stood — splitting it — is an
addition that requires an explicit bounded add budget. A compaction
obligation's `required_compaction_remove_paths` are exactly such explicit
per-member removal allowances. An unmentioned member must survive.
Surviving members must stay in order — unchanged except for their own
authorized leaf edits, where an authorized node permits its complete subtree
(an authorized same-length list-valued leaf replacement survives beside a
neighboring authorized member removal) — additions stay bounded by an
explicit add budget, never by member-slot count or the prior collection
size, and projection applies the same rule when copying. The raw drift
check, the projection membership fast path, and the content-anchored
reconciler enforce this one per-member operation-authority rule through a
single shared membership check, so a raw corrected object and any projected
correction obey identical operation permissions: every authorized
whole-member slot that lacks its own removal allowance must still be
represented by exactly one returned row, and every row beyond those
replacements needs add authority.
When a correction both repairs its authorized whole-member slots and drifts
the rest of the list (unauthorized removals or reordering), the corrected
list itself is never accepted; projection may instead reconcile
content-anchored against the failed output: each unauthorized failed member
that equals exactly one corrected row anchors it, unmentioned or reordered
members are restored from the failed output in original order, an unmatched
corrected row is taken as a replacement only when it attributes to exactly
one authorized slot whose position between anchors is unambiguous — a run
of returned rows shorter than the authorized slots between anchors is an
ambiguous partial mapping and is rejected, never assigned to the first slot
by assumption — and a
vanished authorized member still requires removal authority. Duplicate
content, an unattributable replacement, or an insertion beyond an explicit
add budget is ambiguous and fails closed with no projection. An append or insertion of new members is
authorized only explicitly: an obligation whose allowed_repairs permits `add`
grants a bounded append budget on the collection its paths name (one new
member per named missing literal, at least one); no leaf path implies that
permission. A compaction obligation's exact removal paths fully enumerate the
container they evict from, so the container-root issue path adds no
member-level authority. Any projected correction is fully revalidated before
acceptance.

## Proposal request-scope ownership guard (round 26)

The first-party ownership scope check is occurrence-aware: a B request
description/query field (or an H_init/H_reflect/H_analyse skill field) is
flagged only when at least one ownership-phrase occurrence is affirmative.
An occurrence counts as locally negated only when a not/never cue sits in
the same clause within a bounded window and reaches the phrase through an
"as ..." connector (or a bare determiner); "not only ... but also",
contrastive affirmative phrasing, negations in earlier clauses, and
affirmative occurrences mixed with negated ones in the same field keep the
field rejected. The cross-issuer authorization check uses the same
affirmative-occurrence rule, so a locally negated target-issuer scope
phrase never authorizes an otherwise unbounded competitor request.
First-party-capable source carveouts, target-company-scoped news
semantics, the market-backbone requirement, and PIT/role boundaries are
unchanged. The shared rule is a generic lexical guard, not an NLP parser,
and carries no company- or case-specific exception; phrasing it does not
recognize as clearly local negation stays rejected.

## Need-transition restoration and drift pairing (round 19)

Occurrence-aware need-transition obligations carry the exact runtime-issued
occurrence count (`required_need_occurrences`) of the text they require. The
deterministic need-transition fallback restores by count, not by text
membership: a `restore_exactly` obligation appends the exact required text
until the returned list holds the issued number of occurrences, never
removing, deduplicating, or reordering existing returned rows. A
`replace_with_exact_residual` obligation rewrites one occurrence only at the
returned coordinate it actually names; when the targeted occurrence is
absent, the exact residual is appended and a preserved duplicate of the
prior text is never consumed as the write target.

A whole-member path named by a `restore_exactly` obligation is a prior-state
coordinate, not a returned write target: its projection performs no
coordinate copy at all, because the failed object's row at that index may be
a valid preserved sibling and the prior index may exceed the returned list.
Restoration is content based; a still-missing obligation is appended by the
deterministic fallback, never inferred from an absent index.

When a scoped correction is rejected as drift and no safe projection exists,
the exact failed-object/semantic-failure pairing is preserved: a structured
semantic failure is never overwritten by the generic drift message. The
drift diagnostic is retained separately and reported alongside the semantic
failure, so deterministic recovery and any subsequent feedback keep acting
on the recoverable obligations while unpermitted drift is never accepted and
the raw model response never becomes the accepted baseline.

## Availability and source-time predicate scope (2026-10-01)

A market-data absence predicate must be affirmative, attach to market data itself,
and not cross into a different missing object or denied/conditional claim. Explicit
"not missing market data but missing projections" is not an absence assertion.
Typed repair permissions remain limited to the offending brief/detail.

Future expectation vocabulary and source-request intent share estimate/consensus
and forecast inflections. Fetch/retrieve/inspect/read/check requests remain subject
to the same PIT guards as questions. Explicit pre-cutoff availability may permit
future-period estimates, but cannot exempt a separate source publication or
availability date after cutoff; realized results stay prohibited. These lexical
guards detect declared violations; the resolver's source availability check remains
authoritative and no keyword validator claims complete semantic understanding.
