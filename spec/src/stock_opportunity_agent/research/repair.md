# Structured output mechanical repair

## Ownership

Research-owned deterministic candidate transforms used by the shared structured
role validator. This module does not own schemas, evidence truth, scoring,
promotion or commit pointers. See [stage contracts](stage_contracts.md).

## Contract

JSON text repair and shape-specific transforms retain originals and return
auditable operations. Acceptance always requires the owning complete validator.
Applicable mechanical progress survives into the next correction base even when
other issues remain. Typed issue codes/context authorize unique operations;
diagnostic prose never grants authority. Ambiguous content remains with bounded
LLM correction. Budget/provider/cancellation failures remain control flow.

Routing conflict conversion is mechanical only for `routing_answer_conflict`
with `mechanical_action=context_only_selection`, an exact row path and matching
Signal identity. It removes an unsupported ownership claim while preserving the
selected capability and unresolved need; it cannot invent a replacement answer.

An invalid Basic Info citation is mechanically removable before correction only
when its owning validator marks `mechanical_action=remove_runtime_control_citation`
after an exact match to a separately supplied runtime summary. This does not
make all ungrounded literals mechanical; ambiguous source corrections retain
their existing bounded LLM opportunity. Complete merged validation still owns
acceptance and the underlying computed card remains available.

## Verification

Whole JSON source citations may be restored before LLM correction only when
strict decoding finds one distinct original in the owning case/document scope.
The complete object or array must match, including field sets, array order and
numeric types. Repeated quote keys are admissible only when all repeated values and types
are identical. Conflicting keys, duplicate keys in source originals, non-finite
numbers, partial records and ambiguous originals are ineligible. The owning validator emits an exact leaf replacement
with the original text and required source literal; the shared snapshot-bound
text transform applies that permission, logs it, and reruns the full validator.
It cannot complete missing fields or change a diagnosis, candidate or source ref.

Update diff metadata is mechanical only for the owning typed
`signal_update_diff_metadata_invalid` issue. The stable/candidate pair must pass
baseline validation without its declared diff; only `changed_paths` may be
recomputed. Full revalidation still executes fixture checks, so bookkeeping
normalization cannot hide an invalid candidate or research diagnosis.

Test typed permission rejection, correct sibling preservation, full merged
validation, mixed failures and real production-adapter replay without network.
