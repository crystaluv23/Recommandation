# Signal Mining Agent (LabelAwareMiningController)

Experience memory catalogs additionally support an optional exact `signal_ref`
filter on `inspect_catalog(scope=memory)`. Runtime filters the authoritative
association index before pagination; cards retain current committed performance
and applicable/invalidating conditions. Association is not adoption credit.
New candidate `parameters.usage_context` carries economic/research applicability,
interpretation failure conditions and supplied Experience `related_refs`; unknown
boundaries remain unknown and references must resolve to the authorized index.

## Purpose

Define the controlled, label-aware Signal-mining controller and its shared PIT
Evidence Graph that replace the production H1/H2/H3 and E1/E2 mining chain.
The shadow-acceptance gate defined in the owning action plan passed on
2026-09-17 (six additional live shadow rounds, all terminal candidate with
invariants clean, plus two committed production cycles): the production
mining entry is now the controller, dispatched whenever a frozen v8 sampling
manifest is active and the mining model exposes a JSON role caller. The
legacy H/E chain remains callable for read-only history replay and for
H/E role-protocol mining models; archiving the legacy production path
follows the repository removal discipline after the post-cutover
observation cycle.

## Invariants

The live role adapter shares the fixed source-fact instruction used by extraction,
research and retrospective roles. Preserve the source's object, unit, currency,
period and event identity; project cost is not a disclosed contract price, and
several attributes or disclosures of one event are not independent observations.
Inferred relationships remain explicit inferences. This authoring guidance changes
no tool eligibility, termination rule, candidate contract or admission threshold.

### Incremental action-shape correction

Missing/empty/malformed rationale issues use the shared snapshot-bound patch
protocol at the controller's next decision, within its existing correction
budget. The failed action and valid arguments remain fixed; only typed rationale
fields/members can change. Illegal patches keep the same base and permissions.
A nonblank scalar rationale can be uniquely wrapped into one string-array item
by the shared mechanical repair chain, before model correction. No missing
research rationale is invented. Full action, tool/PIT/evidence/state and budget
validation runs again before execution. Unknown action/tool/semantic failures
retain their ordinary correction path until they have owning typed authority.
Controller repair operations are journaled without charging successful tool
budget. Original model replies are preserved by the ordinary response ledger.
Invalid fetch attempts remain diagnostic ledger entries; they never count as
completed fetches or satisfy the proposal/no-pattern exploration prerequisite.
The role adapter selects one output grammar before sending the request: an
ordinary step emits an action with a non-empty rationale array; a step with an
issued `output_patch_contract` emits only `base_hash` and `operations`. The
correction system prompt must not simultaneously require a full action object.
The shared initial Controller prompt and its native
`need_disposition_contract.row_rationale` disclose the same explicit nested
field contract: every `need_dispositions` row's `rationale` is a non-empty array
of nonblank strings; a single reason still uses a one-element array. The row
validator's error repeats that same declaration. This is authoring disclosure,
not a new schema or repair permission: scalar, empty or nested-array row values
remain invalid, valid siblings retain their original persistence semantics, and
only the existing top-level scalar rationale may be mechanically wrapped.
Domain/tool rules remain visible, and the controller still rejects full-object
corrections and validates the assembled action before any tool executes.
The global prompt may consolidate repeated prose while retaining every action,
field/enum, state and budget exception, PIT/evidence/namespace rule, candidate
and admission obligation, memory/backlog access path and terminal condition.
It is not shortened by removing capabilities for a favorable module. Keep the
shared row-rationale/source-fact instructions and normal/typed-patch output
branches verbatim. Compare complete contractual meaning and actual composed
request bytes; text equality, savings arithmetic and offline tests alone do
not establish fresh semantic behavior.

### Explicit request budgets at the role boundary

Tool counters do not describe LLM request cost. A runtime may explicitly bind
the role instance's single-request byte-plus-output limit, cumulative logical
reservation limit and/or call limit. Omitted limits remain unknown, not inferred
from unrelated H1, tool, memory or provider ceilings. Production controller
construction forwards the existing Mining model's single-request limit only;
it does not invent an aggregate/seed/cycle limit.

When any such limit is supplied, the actual decision payload adds a separate
runtime-owned `request_budget`: supplied limits, consumed logical reservations,
the complete current request's reservation, remaining aggregate allowance after
that request, and the minimum reservation of a subsequent request using the
unchanged shared prompt/output allowance and an empty payload. The latter is a
lower bound, never an estimate of an unknown tool result. Calls used/remaining
are disclosed when capped. Tool-free terminals/dispositions still require an
LLM decision; preserve gaps and choose a supported control-plane terminal when
another request cannot fit. This does not impose an action order, remove tools,
authorize a domain conclusion or change any terminal prerequisite.

Estimation includes the complete normal/typed-patch prompt, wrapper envelope,
identity projection and budget metadata itself. The two self-referential cost
fields use fixed-width decimal strings so inserting their exact values cannot
change their own wire size; all values are exact integers, not host token usage.
Hard rejection uses existing control flow before prepare/dispatch, never a
research verdict or model-content correction. Native malformed, identity-rejected
and nonobject answers consume their reservation; pending/pre-dispatch exceptions
do not. Reconstruction replays consumed answers in order and reproduces the
same budget metadata/hash without counting future prepared files or asking
again. Default uncapped adapters preserve their prior prompt/payload/behavior.
Local safety/accounting tests do not prove fresh planning or MVP completion.

### Shared Evidence Graph

S4-to-S5 handoff exports the producing Controller seed's complete cited source
units through one runtime interface. Facts retain whole exact spans and every
binding; relations retain their source operands; raw document/event citations
retain only actually executed read windows with original target, case scope,
document/content hash, offsets, source clocks/type and visibility result. Keep
different event/document targets and case scopes distinct even for the same
raw range. An event's later reads cannot be replaced by its original preview.
Unfetched/unread document body and undisclosed metadata are never exported.
The same citation prerequisite applies before S4 accepts a narrative proposal:
every cited narrative event/document must resolve through this handoff to a
nonempty executed readable window for its own document/hash and case scope.
Reading an unrelated narrative, another case's event or hidden-only markup
does not authorize that citation. A matching document read may support its
fetched case-bound event refs; an event read cannot grant another case scope.
Titles, previews and attribute counts steer search only. The normal Mining
instruction must agree with this gate; an unmet prerequisite is actionable
bounded invalid-action feedback before candidate terminal/sink, not a late
S5 failure, no-pattern or fabricated semantic conclusion. The check proves
read access and lineage, not that a span semantically proves the measurement.

Materialization resolves every citation and relation dependency before sending
spec/skill/tests requests. Missing lineage fails closed as an implementation
prerequisite failure, never a source-absence or no-pattern conclusion. The
handoff does not silently clip fields to600 characters, truncate cited units
to12, or borrow another seed's reads. Complete units enter normal request
accounting; excessive context is a resource failure, not permission to crop
evidence. Materialization egress uses the native reversible identity scope for
source coordinates as well as the existing masked fixture-authoring view.
S5 honors an explicitly bounded caller's request cap and propagates its budget
stop as control flow. It does not infer that the separate H1/controller cap
governs S5; an unconfigured S5 input cap remains unknown. Prospective controls
must freeze the applicable complete-request/correction bounds before dispatch.
This is a runtime source handoff, not a new canonical business record or a new
source read. Historical raw documents, refs, ledger entries and completed
stages remain unchanged. Verify ordinary facts, long facts, later narrative
windows, document-only citations, derived operands, source/case/seed mismatch,
identity masking and actual downstream requests; fixture replay is not fresh
Mining or a published/reused capability.

- The graph is virtual and lazy. Facts project only from documents already
  selected through the authorized resolver and loaded under the point-in-time
  rule `available_at <= prediction_time`, reusing the shared SEC structured
  fact selector and the unchanged-file parse cache. No full-corpus
  materialization exists in any phase.
  `fetch_evidence.query` reaches the shared concept selector for each selected
  structured document, within the same12,000-character projection limit. It
  ranks complete existing concept units without changing source selection,
  periods, values, namespace, literal spans or ref identity. An omitted concept
  may therefore be sought with the existing targeted fetch; no-query projection
  remains identical. Query coverage counts literal terms present in actually
  projected fact bindings/spans or disclosed narrative excerpts, never merely
  in an unprojected document. A lexical match does not establish answer
  sufficiency, comparability, semantic equivalence or source completeness.
- Every Fact node binds concept, unit, period, value, an opaque document ref,
  a verbatim exact span, the content hash, and availability time as one
  indivisible unit. A character window may never present a number detached
  from its concept/unit/period binding.
  New fact identity includes the case scope. New narrative event identity binds
  document id/hash and case scope, independent of excerpt length/query. Shared
  documents at different cutoffs therefore retain separate case observations;
  fetch replay within the same case reuses identity. Historical ledger refs and
  authored artifacts remain original rather than rehashed in place.
  Fact projection reads `value` only for the exact typed accession schema and
  `val` only for legacy nested records, without fallback between the fields or
  rewriting source rows. Roles derive from actual period end within the
  projected group, not record index: every latest-end alternative stays latest.
  Date ordering and basis identity use parsed dates, never lexicographic raw
  date spellings. Fact fields, source literals and unchanged identities remain
  preserved. The user-approved namespace repair adds optional `taxonomy: str = ""`
  to EvidenceFact. New projections copy it from the shared source context for
  both typed accession rows and legacy nested Company Facts. It travels with
  serialized facts, fact-read bindings and their ledger output hashes. No source
  text, original artifact or existing position-bound fact ref is rewritten.
- Automatic same-concept pairs are scoped to case/concept/unit/document and
  content hash and a known, nonblank taxonomy. An old typed whole-row span may
  establish taxonomy when the optional field is absent; an old legacy leaf span
  cannot. Unknown or conflicting field/literal taxonomy does not authorize an
  automatic pair or unique-basis scalar. Old facts remain readable and explicitly
  requested generic arithmetic retains its existing permissions.
  Within that scope, each latest current period has at most one nearest earlier
  period satisfying the existing comparable-duration predicate. Conflicting
  values at either operand period prevent that pair; they do not remove an
  independent unambiguous duration or currency pair. Equivalent duplicate
  operands may share one deterministic citation without counting new evidence.
  No automatic pair stitches different documents or chooses a currency,
  duration, amendment or source revision. Explicit arithmetic and case-local
  co-occurrence retain their existing cross-document permissions.
  Current derived same-concept relations are recomputed after each fetch and
  stale automatic relations removed when their basis changes. Historical ledger
  entries and already requested arithmetic are never rewritten.
  Controller group scalars and the local closure/replay consumers reuse one
  private unique-basis selector rather than dictionary last-write. A scalar is
  filled only when the available latest fact or document-local pair is uniquely
  established; ambiguous alternatives remain in the complete fact directory,
  with a brief working-view ambiguity disclosure. Closure numeric consumption
  requires finite values and finite derived ratios; nonfinite/overflow inputs
  remain unavailable rather than negative evidence. H1 measurable coverage
  reuses the same private row-pair selector within its existing source-proven
  taxonomy/concept/unit group: its count means at least one valid local pair,
  not a selected unique concept-level measurement. A valid duration can count
  despite another unresolved duration; concept-only scalars still require one
  unique basis. Projection omissions remain partial coverage, never source
  absence. No measurement or compute-rule schema is changed. Diagnostic arrival is not admission or
  proof of an economic comparison, source priority or prediction benefit.
  The namespace-field option was explicitly approved by the user on 2026-10-22.
  Verification must include the original same-document two-namespace false pair,
  complete same-namespace positives in both shapes, unknown legacy snapshots,
  contradictory typed provenance, serialization/readback and actual fact-read
  ledger consumption. This repair alone does not prove fresh Mining capability.
- Relation nodes are constructed only by deterministic code within three
  bounded scopes: same-concept record pairs under the existing
  comparable-period rule; numerator/denominator pairs computed only when
  `compute_statistic` is explicitly requested under its frozen rule
  vocabulary; and co-occurrence among facts inside documents of one case that
  were already fetched. There is no cross-case fact enumeration, no
  all-pairs relation construction, and no precomputation of unrequested
  combinations. Graph extent therefore equals requested extent and inherits
  the frozen budgets.
  Every model view also carries runtime-owned tool contracts: the exact frozen
  compute rule enum, two numeric operands from one case in supplied order, and
  read target fields/exclusive selection/window limits with their budget class.
  The catalog contract also names its default scope, scope-specific budget
  classes and currently allowed scopes: `signals`, `evidence` and `backlog`
  charge light; `memory` charges browse. An available `inspect_catalog` action
  authorizes only those allowed scopes, not every variant. Budget rejection
  reports the requested scope and remaining allowed scopes; the next decision
  may choose another action. No budget is transferred or increased.
  Numeric computation rejects non-finite operands/results and a zero ratio
  denominator with a typed validation error before adding a relation or charging
  a successful action. It does not substitute an aggregate, change operands or
  choose a research conclusion. Existing accepted work remains intact.
- Narrative evidence enters as bounded event views with exact spans and
  source lineage; it never synthesizes numeric facts. Narrative events
  project only from the narrative source families (`filing`, `transcript`,
  `news`): structured families that project no facts — price series, raw
  provider envelopes — remain fetched documents with ledger coverage and are
  never laundered into narrative events. Event excerpts reuse the production
  visible-text projection with its substantive anchors, so SEC SGML/HTML
  boilerplate never occupies an event slot.

### Tool surface

- `inspect_catalog(scope=memory)` browses the complete runtime-supplied experience
  index, with optional `level` filtering and cursor pagination; `item_refs` reads
  1-3 authorized item or source originals. The 48KB whole-read/cumulative original
  disclosure ceiling is explicit. Accepted reads survive subsequent decisions.
  Both browsing and reads charge the existing browse budget, so the four light
  evidence-directory actions cannot make omitted experience unreachable. This
  adds no arbitrary file access or new evidence tool. The controller also receives
  bounded Slow method memory, including the new cross-round reflection layer.

- Exactly three runtime-owned tools exist in the first version:
  `fetch_evidence`, `compute_statistic`, and `read_span`. General search,
  arbitrary code execution, arbitrary file reads, and candidate mutation are
  not tools and must not be added without a spec change. Every tool call is
  executed by the runtime, enforces point-in-time and identity masking on
  outputs, charges the shared attempt/cost ledger, and appends one
  mining-ledger entry whose input and output hashes are recorded.
- `fetch_evidence` returns, together with its bounded results, the requested
  source family, query, window and case refs, the selected documents/facts/
  relations, the documents or concepts excluded by limits, query coverage,
  whether unread same-source evidence exists, and per-item content hashes and
  PIT verdicts. A bounded view never proves absence: insufficient coverage
  may support only `evidence_unavailable`, never a domain claim that a fact
  does not exist.
  A multi-case fetch preserves whole-request coverage in the existing ledger
  fields: matched query terms and excluded document ids are unions across cases,
  query sufficiency requires every case's declared query coverage, and unread
  same-source coverage is true when any requested case has omitted documents.
  The last case may not overwrite earlier coverage. Runtime action receipts
  count newly added unique fact and relation refs separately from narrative
  events and previously known refs. Repeating a fetch retains its source refs
  and charged action but reports zero new nodes when the graph is unchanged.
  This changes neither query selection nor measurement/admission semantics.
- Narrative read access (action plan v2, Phase 1): raw narrative text is the
  authoritative narrative evidence. `NarrativeSpan` carries `event_ref`,
  `case_ref`, `document_ref`, `source_family` (normalized family, not raw
  source_type), `title` (deterministic, masked), `excerpt` (masked visible-text
  summary, discovery-only), `exact_span` (verbatim raw-content window, held
  unmasked inside the runtime-owned ledger), `content_hash`, `available_at`,
  and `published_at`. `event_ref` identity is stable across paginated reads so
  ledger replay keys never break.
  Directory rows expose all current `(case_ref,event_ref)` bindings for the
  unique document/hash. Event reads expose the selected case; document reads
  expose every fetched case binding. Structured fact reads expose their selected
  case, document ref, content hash and source availability; their ledger scope
  retains the same case. Read receipts retain that scope after
  later actions. Labels stay in the already-authorized Slow label map and are
  never added to blind-stage sources. Attribute rows also bind case scope while
  scanning each immutable document once, including shared-case observations.
- `read_span` accepts exactly one of `fact_ref`, `event_ref`, or
  `document_ref`; narrative/document reads take bounded `offset`/`length` and
  return masked windows of the verbatim source text. Budget dimension is
  determined by target class: fact reads charge the heavy budget, event and
  document reads charge the separate browse budget. The browse budget
  (initial ceiling 24 steps with per-step byte caps on catalog, summary, and
  body) is a shadow-phase ceiling, frozen into the run contract only after
  p50/p95 wire-token calibration; it never competes with the heavy budget.
- `inspect_catalog` gains an optional `scope`: `signals` (stable Signal
  catalog, the existing behavior) or `evidence` (the fetched-evidence
  directory organized as family -> time window -> document refs with masked
  titles and bounded summaries). Catalog and summary output is
  `discovery_only`: it may steer search but can never be cited as candidate
  evidence; only raw spans (facts, events, documents read through
  `read_span`, or relations) are evidence-usable.
  Signal working cards include the source-authored definition, output schema,
  execution descriptor, retrieval/time/comparison rules and parameters, plus
  original hash/read size. Cards are whole-entry paginated; omitted cards remain
  addressable. `inspect_catalog(scope=signals,item_refs=[versioned refs])` reads
  whole immutable `{spec,skill}` bundles within the same 16KB byte cap used for
  backlog content. There is no arbitrary path/tool or version guessing. Runtime
  verifies original identity/hash before masking only the model view. Missing
  content is disclosed as unavailable. Source specs/skills are not corpus facts
  and their presence does not prove semantic need coverage. Inspection retains
  the existing light budget charge; budgets and promotion gates do not change.
- No-match never equals negative: a read or query without a match yields
  unavailable or coverage insufficiency, never a domain claim.
  Fixed directory guidance names the actual pagination operation: copy the last
  result's `next_cursor` into the next evidence-catalog request. Without a new
  fetch, omitted cursor or zero repeats the first page; this is not additional
  evidence coverage. Each page is a subset of the fetched directory, and unread
  cards remain unknown. Before a positive/control narrative comparison, bind the
  chosen document/event to its case bindings and the current label map. This
  clarifies existing tool semantics without imposing a coverage quota, candidate
  outcome, additional tool call, or new admission gate.

### Modality exploration obligation (action plan v2, Phase 2)

- The controller view and ledger carry runtime-computed `modality_coverage`
  for the structured and narrative modalities: `{available, explored,
  status}`. Availability derives from the value-free measurable-evidence
  manifest and available source families; exploration derives from actual
  ledger fetch/catalog/read actions.
- While either available modality is unexplored, domain terminal actions
  (`propose_candidate`, `record_no_pattern`) are inadmissible; the bounded
  correction names the remaining modality and legitimate exploration actions.
  Control-plane terminals (`record_deferred` and its
  `deferred_budget`/`evidence_unavailable` outcomes, correction-exhaustion
  `technical_failure`) always satisfy the obligation — the obligation binds
  exploration opportunity, never candidate outcomes. No quota forces a
  candidate from either modality, and none may be added merely for balance.
- The mining audit reports the modality metrics: eligible narrative seed
  count, exploration completions, typed unavailability, narrative reads,
  candidates, materializations, and validations, so reflection can consume
  real modality footprints across cycles. The audit also names the staged
  narrative candidates (`narrative_candidate_refs`), and each cross-cycle
  modality footprint entry carries the prior cycle's staged candidates'
  real check-cohort outcomes (signal ref, disposition, availability,
  decisive, and tp/fn/fp/tn) — a semantic family whose fires never overlap
  the positive class is a demonstrated predicate-label mismatch the next
  proposal must not repeat.

### Narrative candidate predicate (action plan v2, Phase 3)

- A narrative candidate's `measurement` may carry a `predicate` object:
  `{modality: "narrative", source_families, lookback_days,
  semantic_condition, threshold: {field, operator, value}}`. The runtime
  checks mechanically: the predicate's families intersect the families of the
  cited narrative evidence; the cited evidence includes at least one raw
  narrative ref (event or document); every cited ref resolves in the ledger;
  amount/date/window claims ride on verbatim spans, not on summaries.
  Semantic satisfaction is judged only downstream by fixtures, holdout, and
  the paired gates — the predicate never bypasses them.

### Evidence priority and the optional attribute projection (action plan v2, Phase 4)

- Raw narrative spans outrank every projection: an AttributeProjection may
  index, aggregate, rank, and feed reflection, but may never be the only
  evidence for a narrative candidate and may never interpret a projection
  miss as the event's absence. Low-frequency events stay discoverable through
  the raw path regardless of any projection threshold.
- The projection layer is optional and contract-bound: its vocabulary,
  ordering, rules, and input corpus hash are frozen artifacts (a zero-call
  corpus derivation over the dev cohort); projection outcomes are typed
  `projected_positive`, `projected_counter`, `projected_unresolved`, or
  `projection_unavailable`, and a disagreement between a projection and a raw
  span keeps the raw evidence and disables the projection, never the
  candidate. A new projection kind is an explicit spec/contract extension.
- Repeated fetch/document/event handles must not multiply attribute hits: one
  immutable document identity and content hash contributes once to a digest.
  Within a controller, cache only the pure per-document attribute rows, keyed by
  document identity/hash, source family metadata, availability, the current
  event-to-case association and frozen vocabulary hash. New documents, changed
  associations or vocabulary cannot reuse stale rows. Reassemble case/label
  aggregates for every view; label changes do not require another raw scan.
  This cache is disposable and is rebuilt on recovery. It changes no fetch/read
  charge, ledger, evidence span, PIT filter, candidate authority or raw read
  accessibility. A cached miss still cannot establish absence. Duplicate hits
  in older diagnostic views remain immutable rather than rewritten.
- Known interim property (until the projection lands): narrative proposals
  ground in qualitative raw reading with no cheap cross-group contrast
  instrument before the paired gate; the gate remains the arbiter, and
  first-round low narrative proposal counts must not be read as failure.

### Migration boundary (action plan v2)

- The narrative interface, modality obligation, predicate contract, browse
  budget, and any projection hash require a new run contract and successor
  workspace. V98 and earlier workspaces stay read-only; their contracts and
  history chains never gain the new fields. Rollback means freezing a fresh
  successor from the same committed history with the narrative modality
  disabled in its contract configuration — there is no runtime feature flag.
- Case briefs (masked per-company introductions) are explicitly deferred:
  recorded here so the deferral is not silent, to be designed into a later
  contract version.

### Controller discipline

- The controller is a fixed state machine, not a general agent framework.
  Each model step returns exactly one action from the closed enum
  `inspect_manifest`, `inspect_catalog`, `fetch_evidence`,
  `compute_statistic`, `read_span`, `compare_groups`, `propose_candidate`,
  `record_need_dispositions`, `record_deferred`, `record_no_pattern`. The runtime alone decides
  admissibility, executes the action, writes the ledger, enforces
  termination, and admits a candidate into validation.
- Seed states move only along `ready -> exploring -> evidence_ready ->
  candidate_proposed -> locally_validated -> terminal`. The disjoint
  non-domain terminal states `technical_failure`, `evidence_unavailable`,
  `deferred_budget`, `no_pattern_with_coverage` may never be conflated with
  one another, and a technical failure may never be counted as a domain
  no-pattern.
- Budgets are dual-dimension and frozen in the run contract: heavy actions
  (`fetch_evidence`, `compute_statistic`, `read_span`, `compare_groups`,
  `propose_candidate`) share a per-seed cap, initially 12; light actions
  (`inspect_manifest`, `inspect_catalog`) draw from a separate small cap,
  initially 4, so enumeration is not starved by evidence work. All actions
  remain under the existing attempt/cost and token ceilings. Numbers are
  finalized from offline replay; the model can never adjust them.
- A heavy action requested after the heavy budget is exhausted is a
  runtime-owned state inadmissibility, not a model contract fault. The model
  receives one bounded chance to switch to an admissible action (including
  `record_no_pattern` with ledger-backed coverage); a repeated inadmissible
  heavy action ends the seed deterministically as `deferred_budget` with a
  resumable ledger, never as a technical failure.
- Every model view carries runtime-owned progress surfaces so the model can
  observe its own tool results: an `evidence_digest` (fetch count, families,
  fact/event/relation counts, per-concept positive/control case coverage) and
  the `last_action_result` of the previous executed action. A view that hides
  what fetches already collected invites redundant sweeps and is a defect.
- Successful `inspect_catalog` responses additionally survive intervening
  actions in `catalog_observations`. Retain only the exact runtime-issued
  response, scope, arguments, ledger action id and response/source-snapshot
  hashes; never populate unrequested pages, originals or semantic notes. A
  repeated request replaces its prior observation and moves it to the front,
  while charging the unchanged scope budget. Select most-recent complete
  responses, at most8 responses/32,000 UTF-8 JSON bytes; disclose the arguments,
  hash and required bytes of omitted/oversized responses without clipping.
  All four scopes (`signals`, `evidence`, `backlog`, `memory`) use this same
  working surface, including whole-original reads. Larger legal responses can
  remain available only in the previous action and existing canonical source
  disclosures; the working page explicitly reports their size.
  Observations are historical tool responses, not current catalogs: their
  source-snapshot hashes bind the issued source population, source versions,
  case scopes and relevant state. Evidence population bindings preserve
  first-seen immutable narrative-document order, event order and case scopes,
  excluding read progress: ordinary reads/computation preserve directory
  pagination, so the saved next cursor remains usable without re-reading page
  zero. A later fetch that changes that population can change pagination;
  historical `read_windows` never asserts current read status. Existing live
  progress remains authoritative and a required current-catalog refresh uses
  the ordinary charged action. Runtime handles are
  retained before native per-request identity projection, never cached wire
  aliases. This surface adds no action, read allowance or semantic authority;
  the entire response/disclosure and duplicate last result count in the
  unchanged whole-request budget.
  Backlog context does not itself grant disposition authority. A backlog item
  visible in an included observation can enter `allowed_need_refs` only while
  still pending and exactly matching its current whole original or source
  hash. Omitted, oversized, changed and already staged items grant no authority;
  the disposition base hash and all existing typed validation remain current.
  Views do not mutate observations, sources, budgets, ledger or S5 evidence;
  replaying the accepted tool actions deterministically reconstructs them.
- Narrative read progress survives intervening catalog and computation actions.
  Every unique immutable document/hash/raw range retains its receipt metadata
  (coordinates, readable status, hash and next readable offset), without another
  raw-text copy. Repeated reads update a count instead of growing the view.
  A bounded whole-receipt page discloses omitted ranges; the evidence directory
  also lists each document's read windows. Progress metadata proves a read,
  not its semantic sufficiency, and does not alter existing budget charges.
  Metadata-only progress is insufficient working evidence: after another action,
  the model must still be able to compare the actual meaning of already-read
  windows. Expose a separate `narrative_read_evidence` working page derived only
  from the same executed source-bound units retained for materialization. Keep
  complete masked readable text, immutable document/content/raw-window hashes,
  raw coordinates, visibility, source type/clocks, actual read target refs and
  case scopes. A document alias or repeated read may coalesce identical raw
  units; union only scopes/targets actually read, never grant another case's
  event access. Unread body, hidden markup and undisclosed metadata stay absent.
  Preserve the original receipt directory separately; do not replace it with
  model-written summaries, inferred findings or semantic notes.
  Select most-recently-read complete units, at most12 units/40,000 UTF-8 JSON
  bytes, allowing two ordinary maximum4000-character Unicode windows plus
  provenance to coexist. Include explicit counts/coordinates/required sizes
  for omitted or oversized units and the ordinary `read_span` revisit action;
  no body unit is clipped. Revisit remains a charged source read and moves its
  existing unit to the front. This adds no new tool, source read allowance,
  free extraction, canonical schema or semantic authority. The entire actual
  request, including this page/disclosure and repeated last result, remains
  subject to the existing single/aggregate/call budget. Identity masking must
  cover complete retained text through the same native transport; canonical
  originals, ledger bytes and S5 source units remain unchanged. Replaying the
