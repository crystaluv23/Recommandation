## Expectation 2 — magnitude factors mined: FAIL in V140 (machinery bug), fixed for V141

`slow_input.json` was correctly provisioned: 7122 feedback rows including the
committed round's `magnitude_feedback` unit (confusion matrix, TP conditional
accuracy 0.5) plus 70 magnitude-mentioning rows, and the ge3 research target
with a 565-case group manifest (159 `ge3_high` / 406 `ge3_low`) and a
class-balanced issuer-disjoint 32 dev / 16 check sampling.

But the multi-axis audit shows both ge3 controller seeds failed with
`"research_axis requires a stable axis_id"`:
`ResearchTargetContract.descriptor()` exposes `target_id`, while
`LabelAwareMiningController` requires `research_axis["axis_id"]`. The direction
axis worked only because its dict is built inline with `axis_id`. The axis-level
audit still reports status `completed`, masking the seed failures — the
magnitude track could never mine in production.

Why offline suites missed it: `test_controller_runs_direction_and_magnitude_as_separate_axes`
mocks `_run_controller_mining_axis` at exactly this boundary, and the C5/C8
target tests exercise the legacy H/E role path, not the production controller ×
target combination. Fix `628516d` passes the descriptor with an explicit
`axis_id`; the new regression test drives the real controller path and was
red-green verified (fails on the old code). 1089 tests + lint pass.

## Decision

Per the user's early-termination criterion (magnitude self-evolution invalid),
V140 was stopped (supervisor TaskStop + SIGTERM; workspace consistent — cycle 1
committed, cycle 2 interrupted at proposal stage, 1 in-flight attempt settles
as a transport failure on any later resume). V141 re-freezes the same scope on
the fixed code.
