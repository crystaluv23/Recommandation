# Unavailable-topic finding attribution

The complete native validator admitted an unsupported qualitative finding,
`Customer concentration is weak.`, because it lacked a negation/unknown marker.
Conversely it quarantined an exact independently supported same-topic fact
when another result was unavailable. The repair targets these two demonstrated
errors; it does not close whole F7 or the engineering MVP.

The owning spec now requires independent exact provenance for newly asserted
beliefs/resolutions matching an unavailable Signal's existing whole-word topic.
Retained evidence must keep its accepted tuple and claim. Current evidence must
have an adoptable exact tuple/index, valid publication cutoff, and an exact
raw/full readable literal or existing canonical numeric adoption string.
Reference membership, paraphrases, substrings, future sources and bounded
prefix/omission text do not suffice. All other evidence, quantity, need and
terminal checks retain authority. The indexed member remains the remove-only
atomic repair unit; no clause splitting, field transfer or new author call.

The initial [author check](../runs/diagnostics/unavailable_topic_grounding_20261021_v1/pre-connected-safe-summary.json)
passed the unchanged six old repair methods and seven new methods. The
[initial independent review](../runs/diagnostics/unavailable_topic_grounding_20261021_v1/pre-connected-independent-review.json)
passed 28 controls, contrasting old full-parser weak acceptance with rejection
and exact native single-call quarantine, and old exact-source rejection with
new full preservation. Those are synthetic native checks, not fresh model
obedience or live source admission.

Root's broader [281-test connected run](../runs/diagnostics/unavailable_topic_grounding_20261021_v1/root-connected-tests.log)
found two regressions in existing duplicate-need restoration tests. The new
predicate eagerly projected independent evidence even when the batch had no
unavailable result. Those tests deliberately supply a minimal positive-result
stub, so this previously irrelevant projection raised TypeError. The initial
candidate is retained byte-for-byte as `pre-connected-*`; the old tests and
production schema must not be weakened to accommodate the new work. The fix
now defers proof construction until an actual unavailable-topic match exists.
It does not add schema compatibility or swallow projection exceptions. One new
test prevents projection for no unavailable result, no matching topic and no
new finding. The author's 16-test run includes both originally failing methods.
Root's [final connected run](../runs/diagnostics/unavailable_topic_grounding_20261021_v1/root-connected-final-tests.log)
passes 282 tests in 3.064 seconds: unchanged/new unavailable tests, temporal
residuals, reflection roles, scoped correction, duplicate needs, retained claims,
quantity/source guards, runtime final context and Signal execution adapters.
Network, subprocess, real-label, repository Raw Info append and full-prepare
tripwires all remain zero. This is scoped connected validation, not a full
repository test run, fresh model trial or actual-stage reexecution.

The [final independent review](../runs/diagnostics/unavailable_topic_grounding_20261021_v1/independent-final-review.json)
reruns the original 28 controls on the final source and adds three no-op

No original small-suite evidence or connected failure log is overwritten.
