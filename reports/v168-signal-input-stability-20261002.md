# v168 Signal 输入稳定性审计与修复

本轮继续整体可靠性与 Slow 因子目标，未完成真实全周期验收。此前 v168 固定 24 案第二 Plan 的四个技术排除中一例为正例，计技术 FN；技术排除率 4/24=16.7%。历史评分、原始请求、标签及提交状态不改。此前四项检测误拒的原响应解析重放见 [报告](v168-runtime-reliability-repair-20261002.md)。

## 此次发现

[实际请求审计](v168-signal-dispute-input-audit-20261002.json)从提交后的 16 个物理观察冲突追查初始请求。12 个冲突存在不同的逐 Signal 可见证据视图：全量文档指纹相同，并不保证预算内展示的片段相同。旧共享队列受同批其他 Signal 的检索词、数值概念和字符竞争影响；仅按文档划分引用权限还允许引用同一文档的同批其他 Signal 专属片段。

另外四个初始视图一致的冲突不能直接归于模型随机性。实际材料涉及文件发布时间窗口与事件发生时间的混淆、缺少明确比较基准却声称下调，以及 correction 中引用范围/既有必需关键词规则。初始请求匹配依据版本、时点、可见内容指纹，不能证明精确 Plan 所有权；审计也没有将初始请求当作最终 correction。

## 修改

每个 Signal 独立生成有界证据视图，组合时只去重拼接，并保持自己的 eligible_projection_ids。两项合并超过字符或完整请求 token 预算时拆分发送，不再牺牲其中一项的证据覆盖。拆分实际调用及 token 累加，剩余预算不足时保留已完成结果；供应商/授权控制异常继续向外传播。

固定提示提前披露已有 result_required_evidence_phrases 校验义务，并明确发布时间与事件窗口按 skill 原定义应用；比较性结论需有明确比较基准或修订陈述。没有修改历史因子定义、降低硬校验、凭空补出语义结论或改写评分。

## 验证与边界

[实际冻结输入重建](v168-canonical-signal-view-replay-20261002.json)比较 30 次实际单项/配对视图，30 次自身引用视图均保持一致，30 次超字符上限需要拆分。0 外部调用，来源 hash 不变。新回归覆盖同文档不同因子、超预算保留兄弟结果、供应商错误传播；更新既有批量测试，验证不再重复制造片段遗漏。

这些检查证明确定性的输入接线和恢复行为，不能证明模型新回答正确、技术排除率已经下降或 magnitude 已提高。下一份真实诊断 v169 仅准备输入，固定 anchor/discovery/validation 案例与标签须再次核验；来源文件比 v168 多八份，因此不能作完全同输入的增益对照。真实运行必须绑定本轮已提交代码。

最终全量回归：1,433 项通过（85.847 秒）；过程中一次提示字符串拼接断句被既有测试捕获，已修正后重跑全量通过。逐 Signal 数据视图重放基于最终源文件 hash。仓库 lint 在提交前执行。
