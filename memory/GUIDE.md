# Memory Guide

Do not read memory at session start. Use this guide only when prior project experience might apply, or when starting work on a specific module and doing the required quick trigger-map scan.

## Consultation and Effectiveness Protocol

1. Scan the trigger map, then read only the matching experience.
2. Check its scope and evidence against current specs, code and user decisions.
3. Apply, narrow or reject it. When this changes a decision, record one sentence
   of evidence in the task's existing review; no separate consultation entry.
4. If the same failure recurs after applying it, follow the mandatory reflection
   in [agent-workflow](../spec/agent-workflow.md): explain why the lesson failed
   and change the next action. Reading again is not the corrective action.

Do not increment `visit_times`, append consultation logs, or commit merely for
reading. Existing fields and [usage_log](meta/usage_log.md) are historical only.
The counters in older experiences do not create an active obligation.

## Review and Retirement

When a lesson repeatedly fails, contradicts current contracts, or adds work
without affecting decisions, narrow its scope, mark it superseded, merge it or
remove its active trigger. Preserve historical evidence. Prefer deterministic
checks for mechanically decidable lessons; research semantics need actual review.
Record changed decisions and pending effects in [reviews](meta/reviews.md).

## Experience Template

```markdown
# <Experience Title>

## Trigger and Scope
When does this apply, and to which version/boundary?

## Evidence and Root Cause
What actually happened? Link exact artifacts; label hypotheses as hypotheses.

## Changed Action
What should be done differently? Which existing guard enforces this, if any?

## Counterexamples and Limits
When does the lesson not apply? What would disprove it?

## Latest Verification
What was verified, at which evidence level? What remains unverified?
```

Only add a reusable, non-obvious lesson. Routine implementation details, repeated
recaps and read receipts do not need memory entries. Rule effectiveness is judged
by changed decisions and outcomes, never by how often a file was consulted.
