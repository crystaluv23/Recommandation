# Intermediate local/Jev guard review

The copied original seven-case probe and two permission cases show that the
first guard prevented the known local and explicit-disabled remote bypasses.
An additional 18-case matrix mechanically matched that intermediate guard.
These checks did not close the design: their three proposer-only negatives
assumed a wider prohibition than the pre-existing Jev contract justified.

Root's independent policy review identified that Jev replaces only the judge's
two closed-choice roles. A local proposer does not require Jev distributions
and must not disqualify an explicitly enabled remote judge by itself.
`hybrid_counterexample.py` loads the exact original committed control module
(SHA in its result), then calls its actual parser and shared factory. The same
synthetic remote-judge/local-proposer fixture was accepted originally and
reached the provider sentinel; the intermediate guard instead rejects it.
No key, HTTP, socket, answer, probability distribution, or logprob was produced.

The expected policy for the fresh final probe is therefore narrower: local
judge/runtime registration/exchange or explicit `allow_external=False` rejects
before provider construction. A local proposer with an explicitly permitted
remote judge retains the existing route. Both-local production for this user
continues to use `parallel_jev_decisions=False` and native local handoff.

Per-result code hashes distinguish concurrent intermediate edits. These are
preserved intermediate results, not a final frozen-run/readiness certificate.
The hybrid comparison imported the intermediate module before reading the
live file hash while the driver was narrowing the guard. Its observed rejection
is retained, but that live-file hash can already identify the subsequent edit;
it does not certify the exact imported intermediate bytecode. The original
Git-80 source is exact. The fresh v3 positive/negative matrix binds the stable
final source and supersedes this concurrent intermediate check.
The ordinary remote route's provider-sentinel positive only proves it remains
selectable. The existing remote Jev transport's complete authorization/cache/
attempt-ledger wiring is outside this native-backend repair and remains
unverified here.
