## Grammar, semantics and admission limits

The present grammar can carry this family: `measurement.observable/value_kind/normalization`, `predicate.modality='narrative'`, nonempty source families, free `semantic_condition`, optional lookback/threshold, falsifiers and ledger refs. `semantic_condition` is not a closed financing/order enum. A dated management ICFR assessment can distinguish an actual material weakness, an explicit contrary assessment, hypothetical risk, disclosure-controls language, significant deficiency and conflicting/ambiguous assessment scope. None requires a new canonical record. `SignalValue` has positive/neutral/negative/unavailable; semantic distinctions can be stated in the definition/skill and interpretation without fabricating numerical direction or stock efficacy.

This is **expressive sufficiency**, not evidence that the fresh model will faithfully choose the intended definition. S5's generic skill prompt fixes qualifying-event=positive, explicit denial=negative and proposals/lookalikes=neutral, with unavailable for genuinely insufficient text. An ICFR candidate must make its semantic classes compatible with those instructions; positive is a predicate class, not automatically favorable stock direction. If its mined definition reverses that meaning or requires a different mapping, preserve the failure and request a concrete design decision; never silently reverse the measurement. A hypothetical-only paragraph does not establish an actual assessment. Off-object or ambiguous/mixed terminology must remain unknown when the candidate's applicability/mandatory evidence is not met. Do not demote ambiguity into neutral merely to pass generic fixture instructions.

Source existence and finite material review do not establish absence on other cases, effect, source completeness or latest truth. Existing validator checks shape/modality, traceability, identity/leakage, uniqueness, fixture execution and literal/PIT evidence; it does not independently prove that an author-created fixture expected value or complete narrative definition is semantically correct. Freeze the four independent original-material controls before authors and keep that oracle out of their requests. Review raw candidate/spec/skill/test meanings against it before accepting a closure claim. Existing tests cover narrative raw-family intersections, modality exploration, materialization-module reuse and exact technical-checkpoint reuse; none is a fresh ICFR capability result.

## Complete node/cost boundary

`StructuredRoleClient` estimator and actual call share reversible source-coordinate/identity projection, source scanner, wrapper prompt, compact sorted UTF-8 message serialization and output allowance. Local reservation is exact message bytes plus allowance, not host tokens/cost. Transport has no hidden identity retry: invalid/guessed replies are returned as typed failures to the owning loop. Controller corrections use its3-consecutive-error allowance (fourth invalid terminates), not caller `max_structured_corrections=1`. Per-request cap in the axis comes only from `mining_model.request_token_budget`; no aggregate is inferred. S5 receives the caller directly and **does not inherit H1/controller caps**. The driver must enforce S5 complete-request, calls and aggregate caps before prepare/receive using that same estimator.
