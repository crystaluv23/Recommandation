## Actual connection map

`mining_agent_tools._facts_from_document` projects complete facts from selected
PIT source documents. `mining_controller._execute_fetch` keeps facts, events,
relations, documents and document/case associations; the ledger stores the
evidence refs and input/output hashes. `read_span` uses the source's exact raw
coordinates, exposes a masked readable projection, and adds document/event ref
to the ledger. Read progress survives later actions as metadata only.

`_execute_propose` checks candidate refs against the ledger, not the later
engine evidence map. The native engine `_run_controller_mining_axis` currently
reads private `_facts` and `_events` and filters candidates' citations. It then
passes that map through `_materialize_controller_candidate` / `_materialize_once`
to each actual spec, skill and tests module. All three call
`_masked_controller_evidence_excerpts`; the helper silently omits unsupported
refs and clips rows/strings. Its masking strips document artifacts and applies
slow-role/validator identities. Existing retrieval-source validation also reads
object `document_ref` attributes, so a mapping-based runtime handoff must keep
the validation connected rather than simply updating the displayed rows.

## Predeclared repair/counterexample obligations

- Export only cited known facts/events/relations or actual document read
  windows, including ordered relation operands. A fetched-but-unread document
  must not export its body or metadata, even after another document was read.
- A document ref may bind multiple fetched cases; an event read remains scoped
  to its selected case. `_read_progress` merges identical document/hash/ranges
  across event and document reads; it is insufficient to establish original
  target/ref/action lineage by itself. Preserve both read receipts independently.
- Export exactly read raw windows, source/hash/availability and offset lineage,
  never the whole unread document or arbitrary metadata. Hidden markup raw text
  may remain runtime evidence but the model gets the existing readable/masked
  projection. Original raw and projected text hashes have different meanings.
- Preserve complete facts/rows beyond 600/12; source completeness remains
  unknown. An oversized complete payload must stop at the existing real request
   caller-configured request budget before dispatch, rather than clip citations
   or silently acquire budget. An unconfigured S5 budget stays unknown; the H1
   or replacement Controller cap cannot automatically be applied to S5.
- Unknown or unresolved references must fail closed before any materializer
  request. Same ref from another seed must not substitute for the candidate's
  own seed binding. Historical helper fact/event callers remain compatible.
- Inspect actual native spec/skill/tests input composition with identity guards,
  source-family validation and budget rejection, clearly labeling any scripted
  module outputs as synthetic and proving no model endpoint was called.
