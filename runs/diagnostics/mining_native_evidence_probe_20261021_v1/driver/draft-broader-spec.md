# One bounded native Mining evidence probe

This diagnostic executes only after root freezes this script, plan, expectations
and exact source/code bindings and explicitly authorizes its sole execution.
It does not modify products, published definitions or completed stages.

The real input is the existing qualified1780 read-only snapshot. Dev8 identities,
company IDs and aware cutoffs come only from the frozen label-free static
inventory; the company ID is the validated canonical case-ID prefix. A
SimpleNamespace supplies precisely case_id/company_id/prediction_time to native
functions. It is not a restored EvolutionCase, full Engine or Discovery object;
no outcomes, approved40 mixed envelope, check cohort or LabelStore are read.

Controls are fixed before execution:

1. For each dev8, native financial fetch cap2 with no query, and separately the
   exact query NetCashProvidedByUsedInOperatingActivities. Record the entire
   eligible candidate set/order, overlap/tie policy, actual selected/excluded
   IDs, availability and source hashes. Queryless results preserve native
   document order; query ties preserve the existing available_at/ID policy.
2. For every uniquely selected original, and independently exact original0671
   and0674, save the original native _company_facts_context groups/complete
   records/literals/offsets/partial/omissions under the existing12000-char cap,
   then native project_facts_from_documents results separately. A nonempty
   value-only context followed by zero facts diagnoses adaptation; empty context
   remains a distinct upstream gate, not evidence of that diagnosis or no data.
3. Clearly authored in-memory legacy val controls cover a normal prior/current
   pair, same-end different duration, same-period conflicting alternatives,
   multiple units, future filed rows and case-cutoff exclusion. They are never
   copies with a real value key renamed to val, nor appended to the view.
4. Two legacy docs with the same concept/unit are projected in both A,B and B,A
   order (B has only one latest row). Native same-concept relation outputs bind
   complete operand identities, periods and units, exposing overwrite/period
   uncertainty without manufacturing a pairing rule. No statistic or ratio is
   calculated; USD/shares is not declared generally invalid.

Synthetic fetch uses an explicitly marked in-memory documents-only interface;
original fetch always uses the actual reviewed store. Direct document projection
has no case cutoff argument, so future-available direct projection is never
mistaken for a failed native fetch PIT filter. Context and fact counts, selection
and source/period semantics are reported independently. No expectation or source
is adapted after observing native results. Correctness expectations retain
uncertainty when a complete same-concept comparable basis is not established.

Execution validates expected Git revision, plan file SHA, all source/code bytes
and fixed output path before an exclusive execution marker. One execution
writes raw native observations, errors and before/after bindings, then seals the
first result. Completed/failed/partial execution is never reentered or retried.
Expected semantic mismatch is retained as completed diagnostic evidence, not a
reason to rerun or change expectations. No future stage is automatically started.

Only the new execution directory is writable. Network/HTTP, models, Signal
execution, Registry freeze/audit, persistent RawInfoStore construction/append,
LabelStore, LockedTest and full execution are forbidden. Empty in-memory parent
RawInfoStore initialization remains allowed for the real reviewed subclass.
No real probe is executed while preparing or reviewing these files.
