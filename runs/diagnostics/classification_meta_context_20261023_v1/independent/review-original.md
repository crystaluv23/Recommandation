## Minimal unified discovery direction

Reusing `ReflectionMemoryIndex.directory(cursor, level, signal_ref)` to expose complete metadata headers for new runtime declaration sources fits the existing native role protocol. Critic uses the same directory through browse_memory; native Mining `_memory_view` uses it through `inspect_catalog(scope=memory)` and can pass the returned source ref to the existing `item_refs` read path. Neither source storage, reader authorization, nor resource caps need expansion.

Compatibility and counterexamples required for that repair:

1. No-new-field legacy records retain their exact directory envelope/items/count/cursor behavior and unchanged persisted/hash representation.
2. Mixed authored items and declaration source headers page deterministically without duplicates, gaps, or a stuck cursor. Headers cannot expose full skill or definition bodies.
3. Exact version filtering includes declarations for the requested Signal, excludes other versions, and preserves existing related-Signal filtering for authored items. Level case includes declaration units; plan/round/cross_round exclude them.
4. Full-envelope budgets count all new keys/headers. Exact-fit works; one-byte-less either moves to another whole entry or exposes a complete oversized reference and advances; a manifest that cannot fit fails explicitly.
5. Long skill/definition bodies remain immutable full-unit reads and may fail under existing 48 KB caps; no excerpt is labelled a complete definition.
6. Actual Critic browse then read and native Mining directory then item_refs read must use the same returned reference and full matching contract. Existing three Critic memory exchanges and aggregate disclosure cap stay intact.
7. Finite budgets are not complete coverage: if reaching a late page consumes all three Critic memory exchanges, an additional read is correctly refused. Exact Signal filtering cannot eliminate a large same-Signal multi-case population. Do not claim arbitrary-case single-call coverage.
8. Native Mining directory is a separate route from the old H1 `request_slow_sources` selector, whose available set is constructed from initial visible refs. A directory-only fix repairs native Mining discovery but does not automatically repair the old selector's omitted source universe; report each actual entry point separately.

## Evidence boundary

This review establishes an offline wiring failure and tests the proposed generic discovery direction. It does not establish fresh-model semantic consumption, live Critic/Slow success, Fast round acceptance, or MVP closure. Initial declaration validation, exact result ownership and anonymous rehashing appear consistent with the scoped implementation reviewed; this report does not replace parent variant tests for those paths.
