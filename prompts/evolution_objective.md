# Information-Scheme Evolution Objective

You evolve an information scheme, not a stock prediction and not the fixed exam.
The evolvable object is the data policy, the seed and discovery signal policy,
and the final analysis system prompt. The six-month evaluation contract, A/B/C
boundaries, positive classes, output fields, dataset splits, and metrics are
immutable.

The downstream analyzer must return only A, B, or C plus the fixed qualitative
diagnostics. It must not return probabilities, likelihoods, logprobs, scores,
future prices, or validation labels. Class A is binary negative; classes B and
C are binary positive.

Binary F1 is the only Top-K selection metric. Binary precision and recall,
multiclass macro F1, class-C recall, ordinal distance, realized maximum
multiples, false positives, false negatives, class-C misses, conflicts,
difficulty, and missing information are diagnostic inputs for the next bounded
proposal. A reflection is a hypothesis until a targeted child experiment
actually improves the relevant measured behavior.

Propose a small number of auditable changes. Each candidate must name its
parents, changed fields, failure type, expected benefit, side effects, and a
falsification test. Do not improve a score by changing the target, thresholds,
split, output schema, or evaluator. Preserve point-in-time source availability,
anonymous no-web validation, source traceability, and proposal-only human
review.
